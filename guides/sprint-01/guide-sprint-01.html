1

C# et WPF, vus depuis PHP

C#, un langage compilé et typé

En PHP, le serveur lit ton code et l'exécute ligne par ligne. En C#, un compilateur lit d'abord tout le projet, vérifie qu'il est cohérent, puis produit un programme exécutable. Une faute de frappe dans un nom de méthode est donc signalée avant de lancer l'application, pas au moment où la ligne s'exécute.

Pour pouvoir tout vérifier, le compilateur exige de connaître le type de chaque variable, de chaque paramètre et de chaque valeur de retour. C'est la principale différence que tu vas ressentir.

Depuis PHP — la même classe dans les deux langages

Une petite classe d'exemple (elle ne fait pas partie du projet), écrite en PHP puis en C# :

Exemple en PHP
namespace App\Models;

class Greeter
{
    private string $name;

    public function __construct(string $name)
    {
        $this->name = $name;
    }

    public function greet(): string
    {
        return "Bonjour " . $this->name;
    }
}

$greeter = new Greeter("Alice");
echo $greeter->greet();
Le même exemple en C#
namespace WpfNotes.Examples;

public class Greeter
{
    private string _name;

    public Greeter(string name)
    {
        _name = name;
    }

    public string Greet()
    {
        return "Bonjour " + _name;
    }
}

Greeter greeter = new Greeter("Alice");
Console.WriteLine(greeter.Greet());
  • Pas de $ devant les variables. Le type s'écrit avant le nom : string name, Greeter greeter.
  • Le constructeur porte le nom de la classe (Greeter(...)) au lieu de __construct.
  • Le type de retour se place devant le nom de la méthode : public string Greet() équivaut à public function greet(): string.
  • On accède aux membres avec un point (greeter.Greet()) au lieu de la flèche ->, et on concatène avec + au lieu de ..
  • $this->name devient simplement _name : en C#, this. est facultatif. Par convention, les champs privés commencent par _ pour les reconnaître.
  • Les méthodes s'écrivent en PascalCase (Greet), les variables locales en camelCase (greeter).
  • Les deux dernières lignes montrent l'utilisation de la classe. En C#, elles ne peuvent pas rester seules dans le fichier : elles se trouveraient dans une méthode d'une autre classe.

WPF et XAML

WPF (Windows Presentation Foundation) est le framework .NET pour construire des applications de bureau Windows. L'interface ne se décrit pas en C# mais en XAML, un langage à balises qui ressemble à du HTML.

Notion — XAML n'est pas du HTML
Une balise XAML crée un objet .NET : <Button> crée un objet de la classe Button, <TextBox> un objet de la classe TextBox. Chaque attribut (Width="900") donne une valeur à une propriété de cet objet. Écrire du XAML revient à construire un arbre d'objets, décrit de façon déclarative.
Depuis PHP — une vue Blade et une vue XAML
Une vue Blade produit du texte HTML, envoyé au navigateur qui le dessine. Une vue XAML produit des objets en mémoire, que ton code C# peut lire et modifier directement : changer le texte d'un champ, désactiver un bouton, remplacer un écran par un autre. Pas de requête, pas de rechargement de page.

Chaque fichier XAML va de pair avec un fichier .xaml.cs du même nom : le code-behind, où tu écris le C# qui réagit à l'interface. Les deux fichiers forment une seule classe ; on verra comment à l'étape 2.

Étape 1 — Créer le projet et installer Material Design

Solution et projet, package NuGet, thème global, anatomie du .csproj.

1.1 — Nouveau projet WPF

Étapes dans Visual Studio
  1. Fichier → Nouveau → Projet…
  2. Choisis le modèle Application WPF (marqué C#, Windows, Bureau), et non « Application WPF (.NET Framework) », l'ancienne technologie.
  3. Nom du projet : WpfNotes.CodeBehind. Nom de la solution : NoteApp. Emplacement : le dossier où tu ranges tes projets.
  4. Laisse décochée la case « Placer la solution et le projet dans le même répertoire ».
  5. Framework : .NET 10.0. Valide.

Visual Studio crée un dossier NoteApp, qui contient la solution et un sous-dossier pour le projet. Ce dossier NoteApp sera la racine de ton dépôt Git, initialisé en fin de sprint. Il contient ces fichiers :

  • NoteApp.slnx — la solution, à la racine du dossier (NoteApp.sln avec une version plus ancienne de Visual Studio : le rôle est le même).
  • WpfNotes.CodeBehind/WpfNotes.CodeBehind.csproj — le projet (on le lit en 1.4).
  • App.xaml et App.xaml.cs — l'application elle-même : ses ressources et la fenêtre qui s'ouvre au démarrage.
  • MainWindow.xaml et MainWindow.xaml.cs — la fenêtre principale, vide pour l'instant.
  • AssemblyInfo.cs — des réglages techniques générés. Tu n'y toucheras pas.
Notion — solution et projet
Un projet produit un seul programme ou une seule bibliothèque. Une solution regroupe un ou plusieurs projets qu'on ouvre ensemble dans Visual Studio. Ici, la solution ne contient qu'un projet. La version MVVM de NoteApp en comptera trois : l'application, une bibliothèque de logique et un projet de tests.
Notion — pourquoi « .NET » et pas « .NET Framework » ?
.NET Framework est l'ancienne plateforme, réservée à Windows et figée à la version 4.8. .NET (sans « Framework ») est la plateforme actuelle, multiplateforme et mise à jour chaque année. Ce cours utilise .NET 10.

1.2 — Installer MaterialDesignInXAML

Depuis PHP — NuGet, c'est Composer
NuGet est le gestionnaire de paquets de .NET, comme Composer pour PHP : tu demandes un paquet, il le télécharge et l'ajoute au projet. Le site nuget.org joue le rôle de Packagist. MaterialDesignInXAML apporte des styles et des contrôles prêts à l'emploi qui suivent les règles de design « Material Design » de Google.
Étapes dans Visual Studio
  1. Clic droit sur le projet WpfNotes.CodeBehind → Gérer les packages NuGet…
  2. Onglet Parcourir, recherche MaterialDesignThemes, choisis la version 5.3.2, installe.

Le .csproj reçoit alors ces lignes :

WpfNotes.CodeBehind.csproj — ajouté par NuGet
<ItemGroup>
  <PackageReference Include="MaterialDesignThemes" Version="5.3.2" />
</ItemGroup>
Ce que fait ce code
Version="5.3.2" fixe une version précise, comme un numéro exact dans composer.json. Le projet compile alors de la même façon sur toutes les machines, même si une nouvelle version du package sort entre-temps.

1.3 — Configurer le thème dans App.xaml

Remplace le contenu généré par :

App.xaml
<Application
    x:Class="WpfNotes.CodeBehind.App"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes"
    StartupUri="MainWindow.xaml">
    <Application.Resources>
        <ResourceDictionary>
            <ResourceDictionary.MergedDictionaries>
                <materialDesign:BundledTheme
                    BaseTheme="Light"
                    PrimaryColor="DeepPurple"
                    SecondaryColor="Lime" />
                <ResourceDictionary Source="pack://application:,,,/MaterialDesignThemes.Wpf;component/Themes/MaterialDesign3.Defaults.xaml" />
            </ResourceDictionary.MergedDictionaries>
        </ResourceDictionary>
    </Application.Resources>
</Application>
Ce que fait ce code
  • Les lignes xmlns… déclarent le vocabulaire que le fichier peut utiliser. xmlns:materialDesign donne accès aux balises de MaterialDesign, préfixées par materialDesign:. On y revient à l'étape 2.
  • x:Class="WpfNotes.CodeBehind.App" relie ce XAML à la classe C# App, écrite dans App.xaml.cs.
  • Application.Resources — un panier de ressources (styles, couleurs…) accessibles depuis toutes les fenêtres de l'application.
  • MergedDictionaries fusionne plusieurs dictionnaires de ressources en un seul. C'est ainsi qu'on importe les ressources fournies par un package.
  • BundledTheme génère toute la palette de couleurs à partir d'une couleur principale (DeepPurple) et d'une couleur secondaire (Lime).
  • Le second ResourceDictionary (le chemin pack://…) apporte les styles Material Design 3 de tous les contrôles : boutons, champs de saisie, cartes…
  • StartupUri="MainWindow.xaml" — la fenêtre qui s'ouvre au lancement.

Le fichier App.xaml.cs généré reste tel quel :

App.xaml.cs
using System.Windows;

namespace WpfNotes.CodeBehind;

public partial class App : Application
{
}
Point de vigilance — selon ta version de Visual Studio
Le fichier généré contient sans doute quelques using en plus, et écrit namespace WpfNotes.CodeBehind { … } avec des accolades autour de la classe. Les deux formes sont équivalentes : namespace …;, avec un point-virgule, s'applique simplement à tout le fichier. L'important est la ligne public partial class App : Application, expliquée à l'étape 2.

1.4 — Le fichier .csproj, ligne par ligne

Depuis PHP — le .csproj joue le rôle du composer.json
Comme composer.json, le .csproj liste les dépendances du projet. Il dit aussi au compilateur comment construire le programme : quel type d'exécutable, quelle version de .NET, quelles options. Visual Studio le modifie pour toi ; savoir le lire évite de deviner.
WpfNotes.CodeBehind.csproj
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net10.0-windows</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <UseWPF>true</UseWPF>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="MaterialDesignThemes" Version="5.3.2" />
  </ItemGroup>

</Project>
Ce que fait ce code
  • OutputType = WinExe — un exécutable Windows sans console noire derrière la fenêtre.
  • TargetFramework = net10.0-windows — .NET 10, avec les bibliothèques propres à Windows dont WPF a besoin.
  • Nullable = enable — le compilateur distingue une valeur qui ne peut pas être nulle d'une valeur qui peut l'être. On l'utilisera au sprint 2.
  • ImplicitUsings = enable — les using les plus courants (l'équivalent des use de PHP) sont ajoutés automatiquement dans chaque fichier.
  • UseWPF = true — fait de ce projet un projet WPF : les fichiers .xaml sont compilés.
  • PackageReference — une ligne par package NuGet, avec sa version exacte.
À tester (F5)
Lance l'application avec F5. La fenêtre générée par Visual Studio s'affiche, vide. Rien de spectaculaire, mais le projet compile et le thème se charge sans erreur.

Étape 2 — La fenêtre principale

Barre d'application, zone d'écran, nom d'un élément.

2.1 — Ce qu'on va construire

La fenêtre principale ne change jamais. En haut, une barre violette avec le titre. En dessous, une zone qui affiche l'écran courant : la liste des notes, ou une note.

L'écran affiché n'est donc pas une nouvelle fenêtre : c'est un objet qu'on place dans la zone MainContent, et qu'on remplace par un autre pour changer d'écran.

2.2 — Le XAML de la fenêtre

Remplace tout le contenu de MainWindow.xaml par :

MainWindow.xaml
<Window
    x:Class="WpfNotes.CodeBehind.MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes"
    Title="WpfNotes"
    Width="900"
    Height="600"
    WindowStartupLocation="CenterScreen"
    Background="{DynamicResource MaterialDesignPaper}"
    FontFamily="{materialDesign:MaterialDesignFont}"
    TextElement.Foreground="{DynamicResource MaterialDesignBody}">

    <DockPanel>

        <!-- Barre d'application : le titre -->
        <materialDesign:ColorZone
            Padding="16"
            DockPanel.Dock="Top"
            Mode="PrimaryMid">
            <TextBlock FontSize="20" Text="Mes notes" />
        </materialDesign:ColorZone>

        <!-- L'écran affiché : la liste des notes ou une note -->
        <ContentControl x:Name="MainContent" />

    </DockPanel>
</Window>
Notion — un élément peut en contenir d'autres
Le XAML forme un arbre : la Window contient un DockPanel, qui contient une ColorZone et un ContentControl ; la ColorZone contient à son tour le titre. Les panneaux (DockPanel, Grid, StackPanel…) n'affichent rien eux-mêmes : leur rôle est de placer leurs enfants.
Ce que fait ce code
  • Title, Width, Height, WindowStartupLocation — le titre, la taille et la position de la fenêtre à l'ouverture.
  • Background, FontFamily, TextElement.Foreground — la couleur de fond, la police et la couleur du texte du thème Material Design. {DynamicResource …} va chercher une ressource du thème par son nom.
  • DockPanel — accroche chaque enfant à un bord (DockPanel.Dock="Top" pour la barre). Le dernier enfant occupe toute la place restante : c'est la zone d'écran.
  • materialDesign:ColorZone — un rectangle aux couleurs du thème. Mode="PrimaryMid" choisit la couleur principale, le violet, et Padding="16" laisse 16 pixels autour du titre.
  • ContentControl — une boîte vide, capable d'afficher n'importe quel contenu qu'on lui donne depuis le C#.
Notion — x:Name, un pont vers le C#
x:Name="MainContent" donne un nom à l'élément. Dans le code-behind, ce nom devient un champ de la classe : à l'étape 3, tu pourras écrire MainContent.Content = …; pour changer l'écran affiché. Un élément qu'on n'utilise pas depuis le C#, comme le titre, n'a pas besoin de nom.

2.3 — Le code-behind de la fenêtre

Remplace tout le contenu de MainWindow.xaml.cs par cette première version :

MainWindow.xaml.cs — première version
using System.Windows;

namespace WpfNotes.CodeBehind;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }
}
Depuis PHP — using, namespace, :
  • using System.Windows; correspond à un use : il rend utilisables les classes de l'espace de noms System.Windows (dont Window) sans écrire leur nom complet.
  • namespace WpfNotes.CodeBehind; s'écrit exactement comme en PHP, avec des points à la place des antislashs.
  • class MainWindow : Window se lit « MainWindow hérite de Window » : le : remplace extends. La fenêtre hérite de tout le comportement d'une fenêtre (s'ouvrir, se fermer, avoir un titre…).
Ce que fait ce code
  • partial — la classe est écrite en deux morceaux : le XAML, que Visual Studio transforme en un fichier C# caché, et ce fichier-ci. partial dit au compilateur « cette classe continue ailleurs ». C'est dans le morceau caché qu'est déclaré le champ MainContent.
  • public MainWindow() — le constructeur, appelé quand WPF crée la fenêtre.
  • InitializeComponent(); — lit le XAML et crée réellement tous les objets qu'il décrit. Sans cet appel, la fenêtre resterait vide.
À tester (F5)
La fenêtre s'ouvre au centre de l'écran avec une barre violette et le titre « Mes notes ». La zone du dessous est vide.

Étape 3 — Deux écrans et la navigation

UserControl, événement Click, conversion de type, superposition dans un Grid, méthodes publiques.

3.1 — L'écran d'une note : NoteView

Notion — le UserControl, un morceau d'écran
Une Window est une fenêtre complète, avec sa bordure et ses boutons de fermeture. Un UserControl est un morceau d'écran qu'on place à l'intérieur d'une fenêtre. Nos deux écrans seront des UserControl, affichés tour à tour dans la zone MainContent.
Depuis PHP — comme un composant Blade
Un UserControl ressemble à un composant Blade (<x-note-card />) : un bout d'interface rangé dans son propre fichier. La différence : c'est un vrai objet, qu'on crée avec new et qui garde son état tant qu'il est affiché.
Étapes dans Visual Studio
  1. Clic droit sur le projet → Ajouter → Nouveau dossier → Views.
  2. Clic droit sur Views → Ajouter → Nouvel élément… → Contrôle utilisateur (WPF) → nomme-le NoteView.xaml. Deux fichiers sont créés : le XAML et son code-behind.

L'écran d'une note contient un champ de saisie et, en bas, un bouton Annuler qui ramène à la liste. Les boutons Enregistrer et Supprimer viendront aux sprints suivants. Remplace le contenu de NoteView.xaml par :

Views/NoteView.xaml
<UserControl
    x:Class="WpfNotes.CodeBehind.Views.NoteView"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes">

    <DockPanel Margin="16">

        <!-- En bas : les boutons d'action -->
        <StackPanel
            Margin="0,16,0,0"
            HorizontalAlignment="Right"
            DockPanel.Dock="Bottom"
            Orientation="Horizontal">
            <Button
                Click="CancelButton_Click"
                Content="Annuler"
                Style="{StaticResource MaterialDesignFlatButton}" />
        </StackPanel>

        <!-- Au centre : le texte de la note -->
        <TextBox
            x:Name="NoteText"
            VerticalContentAlignment="Top"
            materialDesign:HintAssist.Hint="Votre note"
            AcceptsReturn="True"
            Style="{StaticResource MaterialDesignOutlinedTextBox}"
            TextWrapping="Wrap"
            VerticalScrollBarVisibility="Auto" />
    </DockPanel>
</UserControl>
Ce que fait ce code
  • x:Class="WpfNotes.CodeBehind.Views.NoteView" — la classe se trouve dans l'espace de noms …Views, comme le dossier. C'est une convention, la même qu'en PHP avec PSR-4.
  • Margin="16" — une marge de 16 pixels sur les quatre côtés.
  • Le DockPanel place la rangée de boutons en bas (Dock="Bottom") ; le champ de saisie, dernier enfant, occupe tout le reste.
  • StackPanel avec Orientation="Horizontal" — aligne ses enfants côte à côte, ici calés à droite. Il ne contient qu'un bouton pour l'instant.
  • MaterialDesignFlatButton — un bouton sans fond, discret : Annuler est une action secondaire.
  • Style="{StaticResource MaterialDesignOutlinedTextBox}" — un champ de saisie encadré, au style Material Design.
  • materialDesign:HintAssist.Hint — le texte d'indice affiché dans le champ vide.
  • AcceptsReturn="True" et TextWrapping="Wrap" — la touche Entrée crée une nouvelle ligne, et les lignes trop longues passent à la ligne.
Notion — la propriété attachée
HintAssist.Hint n'est pas une propriété de TextBox : elle est définie par une autre classe, HintAssist, fournie par MaterialDesign, et « attachée » au champ. La syntaxe Classe.Propriété="valeur" le signale. Tu en as déjà croisé une : DockPanel.Dock="Top", que le DockPanel parent lit pour placer son enfant.
Notion — l'événement Click
Click="CancelButton_Click" abonne le bouton à son événement Click : à chaque clic, WPF appelle la méthode CancelButton_Click du code-behind. On l'écrit juste après.

Remplace ensuite le contenu de NoteView.xaml.cs par :

Views/NoteView.xaml.cs
using System.Windows;
using System.Windows.Controls;

namespace WpfNotes.CodeBehind.Views;

public partial class NoteView : UserControl
{
    public NoteView()
    {
        InitializeComponent();
    }

    private void CancelButton_Click(object sender, RoutedEventArgs e)
    {
        // Revenir à la liste, sans rien enregistrer
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowAllNotes();
    }
}
Ce que fait ce code
  • private void CancelButton_Click(object sender, RoutedEventArgs e) — la méthode appelée au clic. void signifie qu'elle ne renvoie rien. WPF lui passe deux informations : sender, l'objet qui a déclenché l'événement (le bouton), et e, des détails sur l'événement. On se servira de sender au sprint 3.
  • Window.GetWindow(this) — appelle une méthode statique de la classe Window, c'est-à-dire une méthode qu'on appelle sur la classe et non sur un objet. En PHP, tu écrirais Window::getWindow($this) : C# utilise le point dans les deux cas. Elle renvoie la fenêtre qui contient l'écran.
  • this — l'objet courant, ici l'écran NoteView, comme $this en PHP.
  • mainWindow.ShowAllNotes(); — demande à la fenêtre d'afficher la liste. Le texte tapé n'est enregistré nulle part : il est perdu, c'est le rôle d'Annuler.
Depuis PHP — une variable typée
En PHP, tu écrirais $mainWindow = …;. En C#, on déclare le type de la variable devant son nom : MainWindow mainWindow = …;. Le compilateur vérifie ensuite que tu n'appelles sur mainWindow que des méthodes qui existent vraiment dans la classe MainWindow.
Notion — la conversion de type (MainWindow)
Le type de retour de Window.GetWindow est Window, le type général de toutes les fenêtres. Or la méthode ShowAllNotes n'existe que dans notre classe MainWindow. On écrit donc (MainWindow) devant : c'est une conversion de type, qui dit au compilateur « je sais que cette fenêtre est une MainWindow ». Si ce n'était pas le cas, l'application s'arrêterait sur une erreur à l'exécution.
Point de vigilance — le nom de la méthode doit correspondre
Le texte de Click="CancelButton_Click" doit être identique au nom de la méthode, majuscules comprises. Sinon, la compilation échoue avec un message du type « NoteView ne contient pas de définition pour CancelButton_Click ».
Point de vigilance — ShowAllNotes est soulignée en rouge
Visual Studio signale que ShowAllNotes n'existe pas : c'est normal, tu l'écris en 3.3. Le projet compilera à nouveau à la fin de l'étape.

3.2 — L'écran de la liste : AllNotesView

Crée de la même façon un contrôle utilisateur Views/AllNotesView.xaml. La liste des notes arrivera au sprint 3 ; pour l'instant, l'écran affiche un message et un bouton « + ».

Views/AllNotesView.xaml
<UserControl
    x:Class="WpfNotes.CodeBehind.Views.AllNotesView"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes">

    <Grid>
        <TextBlock
            HorizontalAlignment="Center"
            VerticalAlignment="Center"
            Opacity="0.7"
            Text="Aucune note. Cliquez sur + pour en créer une." />

        <!-- Bouton flottant « Nouvelle note » -->
        <Button
            Margin="24"
            HorizontalAlignment="Right"
            VerticalAlignment="Bottom"
            Click="NewNoteButton_Click"
            Style="{StaticResource MaterialDesignFloatingActionButton}"
            ToolTip="Nouvelle note">
            <materialDesign:PackIcon
                Width="24"
                Height="24"
                Kind="Plus" />
        </Button>
    </Grid>
</UserControl>
Notion — un Grid sans lignes ni colonnes superpose ses enfants
Un Grid sans RowDefinitions ni ColumnDefinitions n'a qu'une seule cellule : tous ses enfants s'y empilent, les uns au-dessus des autres. On s'en sert pour faire flotter le bouton « + » par-dessus le reste de l'écran, aligné en bas à droite.
Ce que fait ce code
  • HorizontalAlignment et VerticalAlignment — la position de l'élément dans sa cellule : centré pour le message, en bas à droite pour le bouton.
  • Opacity="0.7" — le message est légèrement transparent, pour paraître secondaire.
  • MaterialDesignFloatingActionButton — le style du bouton rond « flottant » de Material Design, réservé à l'action principale de l'écran.
  • Le bouton ne contient pas de texte mais une icône : un bouton peut contenir n'importe quel élément. materialDesign:PackIcon Kind="Plus" choisit une icône parmi des milliers, par son nom.

Puis le code-behind, sur le même principe qu'Annuler :

Views/AllNotesView.xaml.cs
using System.Windows;
using System.Windows.Controls;

namespace WpfNotes.CodeBehind.Views;

public partial class AllNotesView : UserControl
{
    public AllNotesView()
    {
        InitializeComponent();
    }

    private void NewNoteButton_Click(object sender, RoutedEventArgs e)
    {
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowNote();
    }
}
Ce que fait ce code
Au clic sur « + », l'écran retrouve la fenêtre, avec la même conversion de type qu'en 3.1, et lui demande d'afficher l'écran d'une note. ShowNote est soulignée en rouge pour la même raison que ShowAllNotes : elle arrive en 3.3.

3.3 — La navigation dans MainWindow

Complète MainWindow.xaml.cs : voici sa version finale pour ce sprint.

MainWindow.xaml.cs
using System.Windows;
using WpfNotes.CodeBehind.Views;

namespace WpfNotes.CodeBehind;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
        ShowAllNotes();
    }

    // Affiche l'écran « liste des notes »
    public void ShowAllNotes()
    {
        MainContent.Content = new AllNotesView();
    }

    // Affiche l'écran « une note »
    public void ShowNote()
    {
        MainContent.Content = new NoteView();
    }
}
Ce que fait ce code
  • using WpfNotes.CodeBehind.Views; — rend utilisables les classes du dossier Views.
  • MainContent.Content = new AllNotesView(); — crée un nouvel écran « liste » et le place dans la zone d'écran. L'écran précédent n'est plus référencé par personne : .NET libère sa mémoire tout seul, comme PHP.
  • public — ShowAllNotes et ShowNote sont appelées depuis les écrans, donc depuis une autre classe : elles doivent être publiques. Une méthode qui ne sert qu'à l'intérieur de sa classe, comme CancelButton_Click, reste privée.
  • Le constructeur appelle ShowAllNotes() : au démarrage, c'est la liste qui s'affiche.

Pour résumer, un clic sur « + » déclenche cette suite d'appels :

  1. WPF appelle NewNoteButton_Click dans AllNotesView.
  2. Cette méthode retrouve la fenêtre et appelle sa méthode ShowNote().
  3. ShowNote() place un nouvel objet NoteView dans MainContent.
Un clic sur Annuler suit le chemin inverse, jusqu'à ShowAllNotes().
À tester (F5)
  1. Au lancement, la liste s'affiche : le message « Aucune note… » et le bouton « + » en bas à droite.
  2. Clique sur « + » : l'écran d'une note apparaît, avec son champ de saisie et le bouton Annuler.
  3. Tape un texte, puis clique sur Annuler : tu reviens à la liste. Le texte est perdu : l'enregistrement arrive au sprint 2.

Fin de sprint : commit & tag

Premier commit du projet. S'il n'existe pas encore de dépôt Git dans ce dossier, initialise-le d'abord :

Terminal — à la racine du dépôt
git init
Notion — pourquoi exclure des dossiers du suivi Git ?
bin/ et obj/ contiennent ce que la compilation produit : ils sont recréés à chaque F5, inutile de les versionner. .vs/ est le cache de Visual Studio, propre à ta machine. C'est le même principe que vendor/ dans le .gitignore d'un projet Laravel.

À la racine du dépôt, crée un fichier .gitignore :

.gitignore — nouveau fichier, à la racine du dépôt
.vs
WpfNotes.CodeBehind/bin
WpfNotes.CodeBehind/obj
Point de vigilance — le .gitignore avant le premier commit
Un .gitignore n'agit que sur des fichiers pas encore suivis. Crée-le avant le tout premier git add ., sinon bin/ et obj/ seraient déjà dans le dépôt.

git commit -m "Sprint 1 : projet WPF + Material Design, fenêtre principale et navigation"
git tag sprint-01
git push -u origin main
