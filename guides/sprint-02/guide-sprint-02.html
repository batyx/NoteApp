Créer et enregistrer une note

L'écran d'une note existe, mais tout ce qu'on y tape disparaît. Dans ce sprint, tu écris la classe Note, tu la transmets à l'écran qui l'affiche, puis tu enregistres son texte dans un fichier. Un message en bas de la fenêtre confirmera chaque enregistrement.

Où en est-on ? Que va-t-on faire ?

À la fin du sprint 1, la fenêtre principale affiche tour à tour deux écrans : la liste (AllNotesView, encore vide) et une note (NoteView, un champ de saisie et un bouton Annuler). On passe de l'un à l'autre avec le bouton « + » et le bouton Annuler. Mais aucune donnée n'existe : le texte tapé est perdu dès qu'on quitte l'écran.

Pour ce sprint : quatre étapes, chacune vérifiable avant de passer à la suivante.

  • Étape 1 — écrire la classe Note, qui représente une note.
  • Étape 2 — transmettre une note à l'écran NoteView, qui l'affiche.
  • Étape 3 — enregistrer la note dans un fichier texte, puis revenir à la liste.
  • Étape 4 — confirmer l'enregistrement par un message en bas de la fenêtre.
1

Étape 1 — La classe Note

Propriétés, valeur par défaut, type nullable, DateTime.

Une note a un texte, une date d'enregistrement, et un nom de fichier sur le disque. Ces trois informations forment une petite classe, sans aucune logique : on la range dans un dossier Models.

Étapes dans Visual Studio
  1. Clic droit sur le projet → Ajouter → Nouveau dossier → Models.
  2. Clic droit sur Models → Ajouter → Classe… → nomme-la Note.cs.

Remplace son contenu par :

Models/Note.cs — nouveau fichier
namespace WpfNotes.CodeBehind.Models;

public class Note
{
    // Nom du fichier sur le disque. Vaut null tant que la note n'a jamais été enregistrée.
    public string? Filename { get; set; }

    // Le texte de la note
    public string Text { get; set; } = "";

    // Date du dernier enregistrement
    public DateTime Date { get; set; }
}
Depuis PHP — une propriété C#

En PHP 8, tu écrirais une propriété publique typée :

Exemple en PHP
class Note
{
    public ?string $filename = null;
    public string $text = "";
    public DateTime $date;
}

En C#, public string Text { get; set; } déclare une propriété : on la lit et on l'écrit comme un champ (note.Text = "Bonjour";), mais get et set indiquent qu'elle est accessible en lecture et en écriture. C'est la façon habituelle d'exposer une donnée en C# : on pourra plus tard ajouter du code dans get ou set sans changer ceux qui l'utilisent.

Ce que fait ce code
  • namespace WpfNotes.CodeBehind.Models; — le dossier Models donne son nom à l'espace de noms, comme pour Views.
  • = ""; — la valeur par défaut : une note neuve a un texte vide.
  • DateTime — le type .NET pour une date et une heure, l'équivalent de la classe DateTime de PHP (ou de Carbon dans Laravel).
  • Les lignes // sont des commentaires, comme en PHP.
Notion — string?, une valeur qui peut être nulle
Le projet active la vérification du null (Nullable dans le .csproj, vu au sprint 1). Un string ne peut donc jamais valoir null ; un string? le peut. On choisit string? pour Filename, parce qu'une note jamais enregistrée n'a pas encore de fichier. C'est exactement le ?string de PHP, avec le point d'interrogation après le type. Le compilateur te préviendra si tu utilises Filename sans vérifier qu'il n'est pas nul.
Point de vigilance — une DateTime n'est jamais nulle
Une DateTime non initialisée vaut le 1er janvier de l'an 1. Pour savoir si une note a déjà été enregistrée, on ne regarde donc pas sa date mais son nom de fichier : Filename == null.
À tester (F5)
L'application se lance et se comporte exactement comme à la fin du sprint 1 : la classe Note existe, mais personne ne l'utilise encore.

Étape 2 — Transmettre une note à l'écran

Constructeur avec paramètre, champ readonly, références, if / else.

L'écran NoteView va maintenant afficher une note précise. Il la reçoit dans son constructeur et la garde dans un champ. Le bouton « + » lui transmettra une note neuve ; au sprint 3, un clic sur une carte lui transmettra une note existante.

2.1 — Le XAML de l'écran

Remplace tout le contenu de NoteView.xaml par :

Views/NoteView.xaml
<UserControl
    x:Class="WpfNotes.CodeBehind.Views.NoteView"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes">

    <DockPanel Margin="16">

        <!-- En bas : les boutons d'action -->
        <StackPanel
            Margin="0,16,0,0"
            HorizontalAlignment="Right"
            DockPanel.Dock="Bottom"
            Orientation="Horizontal">
            <Button
                Margin="0,0,8,0"
                Click="CancelButton_Click"
                Content="Annuler"
                Style="{StaticResource MaterialDesignFlatButton}" />
            <Button Click="SaveButton_Click" Content="Enregistrer" />
        </StackPanel>

        <!-- En haut : la date d'enregistrement -->
        <TextBlock
            x:Name="DateText"
            Margin="0,0,0,8"
            DockPanel.Dock="Top"
            FontSize="12"
            Opacity="0.7" />

        <!-- Au centre : le texte de la note -->
        <TextBox
            x:Name="NoteText"
            VerticalContentAlignment="Top"
            materialDesign:HintAssist.Hint="Votre note"
            AcceptsReturn="True"
            Style="{StaticResource MaterialDesignOutlinedTextBox}"
            TextWrapping="Wrap"
            VerticalScrollBarVisibility="Auto" />
    </DockPanel>
</UserControl>
Ce que fait ce code
  • Le DockPanel range maintenant trois enfants : les boutons en bas (Dock="Bottom"), la date en haut (Dock="Top"), et le champ de saisie, qui occupe tout l'espace restant parce qu'il est le dernier enfant.
  • Le bouton Enregistrer rejoint Annuler dans le StackPanel. Margin="0,0,8,0" sur Annuler laisse 8 pixels à sa droite (l'ordre est gauche, haut, droite, bas) ; Supprimer arrivera au sprint 3.
  • Le bouton Enregistrer n'a pas de Style : il prend le style par défaut du thème Material Design 3, un bouton plein aux couleurs principales. C'est l'action principale de l'écran.
  • x:Name="DateText" — un texte qu'on remplira depuis le C#.

2.2 — Le code-behind de l'écran

Remplace tout le contenu de NoteView.xaml.cs par cette version, dont la méthode d'enregistrement est encore vide :

Views/NoteView.xaml.cs — version de l'étape 2
using System.Windows;
using System.Windows.Controls;
using WpfNotes.CodeBehind.Models;

namespace WpfNotes.CodeBehind.Views;

public partial class NoteView : UserControl
{
    // La note affichée par cet écran
    private readonly Note _note;

    public NoteView(Note note)
    {
        InitializeComponent();

        _note = note;
        NoteText.Text = _note.Text;
        UpdateDisplay();
    }

    private void CancelButton_Click(object sender, RoutedEventArgs e)
    {
        // Revenir à la liste, sans rien enregistrer
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowAllNotes();
    }

    private void SaveButton_Click(object sender, RoutedEventArgs e)
    {
        // Rempli à l'étape 3
    }

    // Affiche la date en haut de l'écran
    private void UpdateDisplay()
    {
        if (_note.Filename == null)
        {
            DateText.Text = "Nouvelle note";
        }
        else
        {
            DateText.Text = "Enregistrée le " + _note.Date.ToString("dd/MM/yyyy HH:mm");
        }
    }
}
Depuis PHP — un champ readonly initialisé dans le constructeur

En PHP 8.1, tu écrirais :

Exemple en PHP
class NoteView
{
    private readonly Note $note;

    public function __construct(Note $note)
    {
        $this->note = $note;
    }
}

C'est le même principe en C# : private readonly Note _note; déclare un champ privé de type Note, qu'on ne peut affecter que dans le constructeur. Ensuite, impossible de le faire pointer vers une autre note par erreur. On peut en revanche modifier les propriétés de la note elle-même (_note.Text = …).

Ce que fait ce code
  • public NoteView(Note note) — le constructeur reçoit maintenant la note à afficher. Pour créer l'écran, il faudra écrire new NoteView(uneNote).
  • NoteText.Text = _note.Text; — recopie le texte de la note dans le champ de saisie (NoteText est le x:Name du TextBox).
  • if (_note.Filename == null) { … } else { … } — le même if / else qu'en PHP. == compare, = affecte.
  • _note.Date.ToString("dd/MM/yyyy HH:mm") — transforme la date en texte selon un format, comme $date->format('d/m/Y H:i') en PHP. Attention aux lettres : MM est le mois, mm les minutes.
  • UpdateDisplay() est une méthode privée : elle donne un nom à un morceau de code et garde le constructeur lisible. Au sprint 3, elle réglera aussi le bouton Supprimer. Pour une note neuve, elle affiche « Nouvelle note » ; la date d'une note enregistrée se verra quand on pourra rouvrir une note, au sprint 3.
  • CancelButton_Click ne change pas : c'est celle du sprint 1.

2.3 — Créer la note et la transmettre

Le constructeur de NoteView exige maintenant une note : il faut la lui fournir. Dans MainWindow.xaml.cs, ajoute using WpfNotes.CodeBehind.Models; en haut du fichier, puis remplace la méthode ShowNote par :

MainWindow.xaml.cs — la méthode ShowNote
// Affiche l'écran « une note », pour la note reçue en paramètre
public void ShowNote(Note note)
{
    MainContent.Content = new NoteView(note);
}

Puis, dans AllNotesView.xaml.cs, crée la note neuve au clic sur « + » :

Views/AllNotesView.xaml.cs
using System.Windows;
using System.Windows.Controls;
using WpfNotes.CodeBehind.Models;

namespace WpfNotes.CodeBehind.Views;

public partial class AllNotesView : UserControl
{
    public AllNotesView()
    {
        InitializeComponent();
    }

    private void NewNoteButton_Click(object sender, RoutedEventArgs e)
    {
        Note newNote = new Note();
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowNote(newNote);
    }
}
Notion — un objet circule par référence
new Note() crée un seul objet en mémoire. Quand on le passe à ShowNote, puis au constructeur de NoteView, on ne le copie pas : on transmet une référence vers ce même objet. Si NoteView modifie _note.Text, c'est bien la note créée dans AllNotesView qui change. C'est exactement le comportement des objets en PHP.
À tester (F5)
Clique sur « + » : l'écran d'une note affiche « Nouvelle note » en haut, et les boutons Annuler et Enregistrer en bas. Annuler ramène à la liste ; Enregistrer ne fait encore rien.

Étape 3 — Enregistrer la note dans un fichier

Champ statique, chemins de fichiers, écriture sur le disque.

3.1 — Où ranger les notes ?

Chaque note sera un fichier .txt, rangé dans un dossier propre à l'application, dans le profil de l'utilisateur. Ce dossier sert à plusieurs écrans : on le déclare une seule fois, dans MainWindow. Ajoute en haut de MainWindow.xaml.cs la ligne using System.IO;, puis, au début de la classe, juste avant le constructeur :

MainWindow.xaml.cs — le dossier des notes
// Dossier où sont rangées les notes, par exemple C:\Users\toi\AppData\Local\WpfNotes\Notes
public static readonly string NotesFolder = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    "WpfNotes",
    "Notes");
Depuis PHP — static, appelé avec un point
static signifie que la donnée appartient à la classe, pas à un objet : il en existe une seule, partagée. En PHP, tu écrirais public static string $notesFolder et tu la lirais avec MainWindow::$notesFolder. En C#, on écrit simplement MainWindow.NotesFolder. readonly empêche de la modifier après son initialisation : c'est presque une constante.
Ce que fait ce code
  • Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData) — demande à Windows le dossier des données locales de l'utilisateur, par exemple C:\Users\toi\AppData\Local. Il diffère d'une machine à l'autre : on ne l'écrit jamais en dur.
  • Path.Combine(…) — assemble des morceaux de chemin en ajoutant les \ au bon endroit. Le résultat : C:\Users\toi\AppData\Local\WpfNotes\Notes.
  • Les arguments sont répartis sur plusieurs lignes pour la lisibilité : pour le compilateur, c'est un seul appel, terminé par ;.
Point de vigilance — using System.IO;
Path, File et Directory appartiennent à l'espace de noms System.IO. Dans un projet WPF, il ne fait pas partie des using ajoutés automatiquement. Sans la ligne using System.IO;, le compilateur répond que « le nom Path n'existe pas dans le contexte actuel ».

3.2 — Écrire le fichier

Dans NoteView.xaml.cs, ajoute using System.IO; en haut du fichier, puis remplace la méthode SaveButton_Click par :

Views/NoteView.xaml.cs — la méthode SaveButton_Click
private void SaveButton_Click(object sender, RoutedEventArgs e)
{
    // 1. Récupérer le texte saisi
    _note.Text = NoteText.Text;

    // 2. Première sauvegarde : choisir un nom de fichier unique
    if (_note.Filename == null)
    {
        _note.Filename = "note-" + DateTime.Now.ToString("yyyyMMdd-HHmmss-fff") + ".txt";
    }

    // 3. Écrire le fichier sur le disque
    Directory.CreateDirectory(MainWindow.NotesFolder);
    string path = Path.Combine(MainWindow.NotesFolder, _note.Filename);
    File.WriteAllText(path, _note.Text);
    _note.Date = File.GetLastWriteTime(path);

    // 4. Revenir à la liste
    MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
    mainWindow.ShowAllNotes();
}
Depuis PHP — les mêmes fonctions de fichiers, rangées dans des classes
C#PHP
File.WriteAllText(path, text)file_put_contents($path, $text)
File.ReadAllText(path)file_get_contents($path) (au sprint 3)
Directory.CreateDirectory(folder)mkdir($folder, 0777, true)
File.GetLastWriteTime(path)filemtime($path)
DateTime.Nownew DateTime() ou now() dans Laravel
Ce que fait ce code
  • 1. Le texte du champ de saisie est recopié dans la note.
  • 2. Si la note n'a pas encore de fichier, on lui en choisit un, à partir de la date et de l'heure à la milliseconde près (fff) : deux notes n'auront jamais le même nom. Les morceaux de texte s'assemblent avec +. Aux enregistrements suivants, le nom ne change plus : le même fichier est réécrit.
  • 3. Directory.CreateDirectory crée le dossier s'il n'existe pas encore (et ne fait rien s'il existe). string path = …; déclare une variable locale de type string. File.WriteAllText crée ou remplace le fichier. On relit enfin sa date de modification.
  • 4. On revient à la liste, comme avec Annuler.
Notion — le compilateur suit les null
Après le if, _note.Filename ne peut plus être nul : soit il l'était et on vient de lui donner une valeur, soit il avait déjà un nom. Le compilateur fait ce raisonnement tout seul et accepte Path.Combine(…, _note.Filename) sans avertissement. Retire le if pour voir : Visual Studio souligne aussitôt _note.Filename en vert.
À tester (F5)
  1. Clique sur « + », tape un texte, clique sur Enregistrer : tu reviens à la liste. Elle reste vide, c'est normal : elle ne lit pas encore le dossier (sprint 3).
  2. Ouvre le dossier des notes : touches Windows + R, tape %LocalAppData%\WpfNotes\Notes, valide. Un fichier note-….txt s'y trouve, avec ton texte.
  3. Crée une autre note : un second fichier apparaît.
  4. Crée une troisième note, mais clique sur Annuler : aucun fichier n'est ajouté.

Étape 4 — Confirmer par un message

Snackbar, markup extension, vérifier un null avant de s'en servir.

Le changement de date en haut de l'écran passe inaperçu. Material Design propose un composant fait pour ça : le Snackbar, un court message qui apparaît en bas de la fenêtre puis disparaît seul. Comme tous les écrans pourront s'en servir, on le place dans la fenêtre principale.

4.1 — Le Snackbar dans la fenêtre

Dans MainWindow.xaml, remplace la ligne du ContentControl par un Grid qui contient la zone d'écran et le Snackbar. Voici le fichier complet :

MainWindow.xaml
<Window
    x:Class="WpfNotes.CodeBehind.MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes"
    Title="WpfNotes"
    Width="900"
    Height="600"
    WindowStartupLocation="CenterScreen"
    Background="{DynamicResource MaterialDesignPaper}"
    FontFamily="{materialDesign:MaterialDesignFont}"
    TextElement.Foreground="{DynamicResource MaterialDesignBody}">

    <DockPanel>

        <!-- Barre d'application : le titre -->
        <materialDesign:ColorZone
            Padding="16"
            DockPanel.Dock="Top"
            Mode="PrimaryMid">
            <TextBlock FontSize="20" Text="Mes notes" />
        </materialDesign:ColorZone>

        <Grid>
            <!-- L'écran affiché : la liste des notes ou une note -->
            <ContentControl x:Name="MainContent" />

            <!-- Zone de notification, en bas de la fenêtre -->
            <materialDesign:Snackbar
                x:Name="MainSnackbar"
                VerticalAlignment="Bottom"
                MessageQueue="{materialDesign:MessageQueue}" />
        </Grid>

    </DockPanel>
</Window>
Ce que fait ce code
  • Le Grid sans lignes ni colonnes superpose ses deux enfants, comme le bouton « + » au sprint 1 : le Snackbar s'affiche par-dessus l'écran courant, aligné en bas.
  • x:Name="MainSnackbar" — pour l'utiliser depuis le code-behind.
  • MessageQueue="{materialDesign:MessageQueue}" — crée la file de messages du Snackbar. Les messages y attendent leur tour : s'il y en a deux d'affilée, ils s'affichent l'un après l'autre.
Notion — les accolades en XAML
Une valeur entre accolades n'est pas un simple texte : c'est une markup extension, un petit objet qui calcule la valeur au moment où le XAML est lu. Tu en as déjà utilisé : {StaticResource …} et {DynamicResource …} cherchent une ressource du thème. {materialDesign:MessageQueue}, elle, crée un nouvel objet file de messages.

4.2 — Une méthode pour afficher un message

Dans MainWindow.xaml.cs, ajoute la méthode ShowMessage. Voici le fichier complet pour ce sprint :

MainWindow.xaml.cs
using System.IO;
using System.Windows;
using WpfNotes.CodeBehind.Models;
using WpfNotes.CodeBehind.Views;

namespace WpfNotes.CodeBehind;

public partial class MainWindow : Window
{
    // Dossier où sont rangées les notes, par exemple C:\Users\toi\AppData\Local\WpfNotes\Notes
    public static readonly string NotesFolder = Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
        "WpfNotes",
        "Notes");

    public MainWindow()
    {
        InitializeComponent();
        ShowAllNotes();
    }

    // Affiche l'écran « liste des notes »
    public void ShowAllNotes()
    {
        MainContent.Content = new AllNotesView();
    }

    // Affiche l'écran « une note », pour la note reçue en paramètre
    public void ShowNote(Note note)
    {
        MainContent.Content = new NoteView(note);
    }

    // Affiche un court message en bas de la fenêtre
    public void ShowMessage(string message)
    {
        if (MainSnackbar.MessageQueue != null)
        {
            MainSnackbar.MessageQueue.Enqueue(message);
        }
    }
}
Ce que fait ce code
  • public void ShowMessage(string message) — publique, parce que les écrans l'appelleront.
  • MainSnackbar.MessageQueue.Enqueue(message) — ajoute le message à la file : le Snackbar l'affiche quelques secondes.
  • if (MainSnackbar.MessageQueue != null) — la propriété MessageQueue est déclarée nullable par MaterialDesign (un Snackbar peut ne pas avoir de file). Le compilateur exige qu'on vérifie avant de l'utiliser, sinon il affiche un avertissement. != signifie « différent de », comme en PHP.

4.3 — Appeler le message après l'enregistrement

Dans SaveButton_Click, juste avant le retour à la liste, ajoute la ligne qui prévient l'utilisateur. Le fichier complet devient :

Views/NoteView.xaml.cs
using System.IO;
using System.Windows;
using System.Windows.Controls;
using WpfNotes.CodeBehind.Models;

namespace WpfNotes.CodeBehind.Views;

public partial class NoteView : UserControl
{
    // La note affichée par cet écran
    private readonly Note _note;

    public NoteView(Note note)
    {
        InitializeComponent();

        _note = note;
        NoteText.Text = _note.Text;
        UpdateDisplay();
    }

    private void CancelButton_Click(object sender, RoutedEventArgs e)
    {
        // Revenir à la liste, sans rien enregistrer
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowAllNotes();
    }

    private void SaveButton_Click(object sender, RoutedEventArgs e)
    {
        // 1. Récupérer le texte saisi
        _note.Text = NoteText.Text;

        // 2. Première sauvegarde : choisir un nom de fichier unique
        if (_note.Filename == null)
        {
            _note.Filename = "note-" + DateTime.Now.ToString("yyyyMMdd-HHmmss-fff") + ".txt";
        }

        // 3. Écrire le fichier sur le disque
        Directory.CreateDirectory(MainWindow.NotesFolder);
        string path = Path.Combine(MainWindow.NotesFolder, _note.Filename);
        File.WriteAllText(path, _note.Text);
        _note.Date = File.GetLastWriteTime(path);

        // 4. Prévenir l'utilisateur et revenir à la liste
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowMessage("Note enregistrée");
        mainWindow.ShowAllNotes();
    }

    // Affiche la date en haut de l'écran
    private void UpdateDisplay()
    {
        if (_note.Filename == null)
        {
            DateText.Text = "Nouvelle note";
        }
        else
        {
            DateText.Text = "Enregistrée le " + _note.Date.ToString("dd/MM/yyyy HH:mm");
        }
    }
}
Ce que fait ce code
mainWindow.ShowMessage("Note enregistrée"); demande à la fenêtre d'afficher le message, juste avant de revenir à la liste. Le message reste visible après le changement d'écran : le Snackbar appartient à la fenêtre, pas à l'écran de la note, qui disparaît.
À tester (F5)
Crée une note et enregistre-la : tu reviens à la liste, et « Note enregistrée » apparaît en bas de la fenêtre, puis disparaît. Crée et enregistre deux notes très vite : les messages s'enchaînent sans se chevaucher.
