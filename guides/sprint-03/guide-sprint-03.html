Où en est-on ? Que va-t-on faire ?

À la fin du sprint 2, on crée une note, Enregistrer l'écrit dans un fichier du dossier %LocalAppData%\WpfNotes\Notes, un message le confirme, et on revient à la liste. Mais l'écran de la liste ne lit pas ce dossier : il affiche toujours « Aucune note », et une note enregistrée ne peut plus être rouverte.

Pour ce sprint : trois étapes.

  • Étape 1 — lire les notes du dossier, les afficher en cartes, et ouvrir une note d'un clic.
  • Étape 2 — supprimer une note, après une boîte de dialogue de confirmation.
  • Étape 3 — chercher comment on pourrait tester ce code, et pourquoi c'est si difficile.

Notion — ItemsControl et DataTemplate
Un ItemsControl affiche une collection : on lui donne une liste d'objets (sa propriété ItemsSource, remplie depuis le C#), et il dessine un élément par objet. Deux réglages disent comment :
  • ItemsPanel — le panneau qui range les éléments. Un WrapPanel les place les uns à côté des autres et passe à la ligne quand il n'y a plus de place.
  • ItemTemplate — le modèle d'un élément, décrit dans un DataTemplate : ici, un bouton qui contient une carte. Il est recopié pour chaque note de la liste.
Depuis PHP — comme un @foreach dans Blade

En Blade, tu écrirais :

Exemple en Blade
@foreach ($notes as $note)
    <div class="card">
        <p>{{ $note->text }}</p>
        <small>{{ $note->date->format('d/m/Y H:i') }}</small>
    </div>
@endforeach

Le DataTemplate joue le rôle du corps de la boucle, et {Binding Text} celui de {{ $note->text }}. La différence : tu n'écris pas la boucle toi-même, l'ItemsControl s'en charge.

Notion — le Binding et le DataContext
Chaque carte générée reçoit sa note dans une propriété nommée DataContext, le « contexte de données » de l'élément. {Binding Text} signifie « affiche la propriété Text de mon DataContext ». C'est ta première liaison de données : le XAML lit lui-même les propriétés de l'objet, sans que tu écrives MonTexte.Text = note.Text pour chaque carte.
Ce que fait ce code
  • ScrollViewer — ajoute une barre de défilement quand les cartes dépassent la hauteur de l'écran.
  • x:Name="NotesList" — pour donner la liste à l'ItemsControl depuis le C#.
  • materialDesign:Card — une carte Material Design, de taille fixe (220 × 160).
  • StringFormat='dd/MM/yyyy HH:mm' — le même format de date qu'au sprint 2, appliqué par le Binding.
  • TextTrimming="CharacterEllipsis" — un texte trop long pour la carte se termine par « … ».
  • Le bouton de la carte appelle NoteCard_Click ; le message « Aucune note » reçoit un nom (EmptyText) pour qu'on puisse l'afficher ou le masquer.

1.2 — Le code-behind de la liste

Remplace tout le contenu de AllNotesView.xaml.cs par :

Views/AllNotesView.xaml.cs
using System.IO;
using System.Windows;
using System.Windows.Controls;
using WpfNotes.CodeBehind.Models;

namespace WpfNotes.CodeBehind.Views;

public partial class AllNotesView : UserControl
{
    public AllNotesView()
    {
        InitializeComponent();
        LoadNotes();
    }

    // Lit toutes les notes du dossier et les affiche
    private void LoadNotes()
    {
        Directory.CreateDirectory(MainWindow.NotesFolder);

        // 1. Une note par fichier .txt du dossier
        List<Note> notes = new List<Note>();
        string[] paths = Directory.GetFiles(MainWindow.NotesFolder, "*.txt");
        foreach (string path in paths)
        {
            Note note = new Note();
            note.Filename = Path.GetFileName(path);
            note.Text = File.ReadAllText(path);
            note.Date = File.GetLastWriteTime(path);
            notes.Add(note);
        }

        // 2. La plus récente en premier
        List<Note> sortedNotes = notes.OrderByDescending(note => note.Date).ToList();

        // 3. Donner la liste à l'ItemsControl, qui dessine une carte par note
        NotesList.ItemsSource = sortedNotes;

        // 4. Le message « Aucune note » n'apparaît que si la liste est vide
        if (notes.Count == 0)
        {
            EmptyText.Visibility = Visibility.Visible;
        }
        else
        {
            EmptyText.Visibility = Visibility.Collapsed;
        }
    }

    private void NoteCard_Click(object sender, RoutedEventArgs e)
    {
        // sender est le bouton cliqué ; son DataContext est la note qu'il affiche
        Button clickedButton = (Button)sender;
        Note clickedNote = (Note)clickedButton.DataContext;

        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowNote(clickedNote);
    }

    private void NewNoteButton_Click(object sender, RoutedEventArgs e)
    {
        Note newNote = new Note();
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowNote(newNote);
    }
}

Le code se lit en quatre temps, numérotés dans les commentaires de LoadNotes.

1.3 — Lire les fichiers : tableau, liste et boucle

Depuis PHP — List<Note> et foreach

En PHP, le même code s'écrirait :

Exemple en PHP
$notes = [];
$paths = glob($notesFolder . '/*.txt');
foreach ($paths as $path) {
    $note = new Note();
    $note->filename = basename($path);
    $note->text = file_get_contents($path);
    $note->date = filemtime($path);
    $notes[] = $note;
}
  • Un tableau PHP accepte n'importe quoi. Une List<Note> ne contient que des objets Note : <Note> indique le type de ses éléments, et le compilateur refuse d'y ajouter autre chose. notes.Add(note) remplace $notes[] = $note.
  • string[] est un tableau de textes, de taille fixe : c'est ce que renvoie Directory.GetFiles, l'équivalent de glob().
  • foreach (string path in paths) se lit « pour chaque path de type string dans paths » — l'ordre est inversé par rapport à PHP, et le type de la variable est indiqué.
Ce que fait ce code
  • Directory.CreateDirectory(…) — si aucune note n'a encore été enregistrée, le dossier n'existe pas : on le crée pour que la lecture ne provoque pas d'erreur.
  • Directory.GetFiles(dossier, "*.txt") — les chemins complets de tous les fichiers .txt du dossier.
  • Path.GetFileName(path) — garde seulement le nom du fichier, comme basename(). C'est ce nom que NoteView réutilisera pour réécrire ou supprimer le fichier.
  • File.ReadAllText(path) — tout le contenu du fichier, comme file_get_contents().

1.4 — Trier : la plus récente en premier

Depuis PHP — comme sortByDesc sur une Collection Laravel

Avec une Collection Laravel, tu écrirais :

Exemple en PHP (Laravel)
$sortedNotes = collect($notes)->sortByDesc(fn ($note) => $note->date)->values();

C'est presque mot pour mot la ligne C# : notes.OrderByDescending(note => note.Date).ToList(). Dans les deux cas, on passe une fonction fléchée qui dit selon quoi trier : fn ($note) => $note->date en PHP, note => note.Date en C#. Elle se lit « pour une note, prendre sa date ».

Ce que fait ce code
  • OrderByDescending — trie par ordre décroissant de la valeur renvoyée par la fonction fléchée, ici la date : la note la plus récente en premier. Ces méthodes de traitement de collections s'appellent LINQ.
  • .ToList() — range le résultat du tri dans une nouvelle liste, comme ->values().
  • NotesList.ItemsSource = sortedNotes; — donne la liste triée à l'ItemsControl, qui dessine aussitôt une carte par note.

1.5 — Afficher ou masquer le message « Aucune note »

Notion — l'énumération Visibility
Une énumération (enum) est un type dont les valeurs possibles sont fixées et nommées, comme les enum de PHP 8.1. Visibility en a trois : Visible, Hidden (invisible, mais garde sa place) et Collapsed (invisible, et ne prend plus de place). On écrit la valeur avec le nom du type devant : Visibility.Collapsed.
Ce que fait ce code
notes.Count est le nombre d'éléments de la liste (le count($notes) de PHP). Si la liste est vide, le message s'affiche ; sinon, il est masqué.

1.6 — Ouvrir une note d'un clic

Ce que fait ce code — NoteCard_Click
  • sender est l'objet qui a déclenché l'événement : le bouton de la carte cliquée. Son type déclaré est object, le type le plus général : on le convertit en Button pour pouvoir lire ses propriétés.
  • clickedButton.DataContext — le contexte de données de la carte, c'est-à-dire la note qu'elle affiche (voir le schéma). Lui aussi est déclaré object : on le convertit en Note.
  • On transmet enfin cette note à la fenêtre, exactement comme le bouton « + » transmet une note neuve.
Point de vigilance — la liste est relue à chaque retour
ShowAllNotes() crée un nouvel écran AllNotesView à chaque appel, et son constructeur relit le dossier. C'est ce qui rend visibles les modifications faites dans une note quand on revient à la liste. Avec quelques notes, c'est instantané ; avec des milliers, il faudrait faire autrement.
À tester (F5)
  1. Au lancement, les notes créées au sprint 2 s'affichent en cartes, la plus récente en premier.
  2. Clique sur une carte : la note s'ouvre avec son texte et sa date d'enregistrement.
  3. Modifie le texte et enregistre : de retour sur la liste, la carte affiche le nouveau texte, et elle est passée en tête.
  4. Rouvre-la, modifie le texte, puis clique sur Annuler : la carte garde le texte enregistré.
  5. Ferme l'application, vide le dossier %LocalAppData%\WpfNotes\Notes, relance : le message « Aucune note » réapparaît.

Étape 2 — Supprimer une note après confirmation

DialogHost, contenu de dialogue, async / await, sortie anticipée.

2.1 — Le contenu de la boîte de dialogue

Material Design affiche ses boîtes de dialogue dans un DialogHost. On lui fournit le contenu à afficher : un message et deux boutons. Crée un contrôle utilisateur Views/ConfirmDialog.xaml :

Views/ConfirmDialog.xaml — nouveau fichier
<UserControl
    x:Class="WpfNotes.CodeBehind.Views.ConfirmDialog"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:materialDesign="http://materialdesigninxaml.net/winfx/xaml/themes"
    xmlns:sys="clr-namespace:System;assembly=mscorlib">

    <StackPanel MinWidth="280" Margin="24">
        <TextBlock
            x:Name="MessageText"
            Margin="0,0,0,24"
            FontSize="16"
            TextWrapping="Wrap" />

        <StackPanel HorizontalAlignment="Right" Orientation="Horizontal">
            <!-- CommandParameter devient la valeur renvoyée par DialogHost.Show -->
            <Button
                Margin="0,0,8,0"
                Command="{x:Static materialDesign:DialogHost.CloseDialogCommand}"
                Content="Annuler"
                IsCancel="True"
                Style="{StaticResource MaterialDesignFlatButton}">
                <Button.CommandParameter>
                    <sys:Boolean>False</sys:Boolean>
                </Button.CommandParameter>
            </Button>
            <Button
                Command="{x:Static materialDesign:DialogHost.CloseDialogCommand}"
                Content="Supprimer"
                IsDefault="True"
                Style="{StaticResource MaterialDesignFlatButton}">
                <Button.CommandParameter>
                    <sys:Boolean>True</sys:Boolean>
                </Button.CommandParameter>
            </Button>
        </StackPanel>
    </StackPanel>
</UserControl>
Views/ConfirmDialog.xaml.cs — nouveau fichier
using System.Windows.Controls;

namespace WpfNotes.CodeBehind.Views;

public partial class ConfirmDialog : UserControl
{
    public ConfirmDialog(string message)
    {
        InitializeComponent();
        MessageText.Text = message;
    }
}
Ce que fait ce code
  • Command="{x:Static materialDesign:DialogHost.CloseDialogCommand}" — au clic, le bouton ferme la boîte de dialogue, sans code-behind.
  • CommandParameter — la valeur que la boîte de dialogue renvoie en se fermant : False pour Annuler, True pour Supprimer.
  • IsCancel="True" et IsDefault="True" — la touche Échap déclenche Annuler, la touche Entrée déclenche Supprimer.
  • Le constructeur reçoit le message à afficher, comme NoteView reçoit sa note.
Notion — écrire un vrai booléen en XAML
En XAML, CommandParameter="True" transmettrait le texte "True", pas le booléen true. Pour obtenir un vrai booléen, on écrit la balise <sys:Boolean>, qui crée un objet de type bool. Le préfixe sys est déclaré en haut du fichier : xmlns:sys="clr-namespace:System;assembly=mscorlib" donne accès aux types de base de .NET, ceux de l'espace de noms System.

2.4 — La suppression dans le code-behind

Remplace tout le contenu de NoteView.xaml.cs par sa version finale :

Views/NoteView.xaml.cs
using System.IO;
using System.Windows;
using System.Windows.Controls;
using MaterialDesignThemes.Wpf;
using WpfNotes.CodeBehind.Models;

namespace WpfNotes.CodeBehind.Views;

public partial class NoteView : UserControl
{
    // La note affichée par cet écran
    private readonly Note _note;

    public NoteView(Note note)
    {
        InitializeComponent();

        _note = note;
        NoteText.Text = _note.Text;
        UpdateDisplay();
    }

    private void CancelButton_Click(object sender, RoutedEventArgs e)
    {
        // Revenir à la liste, sans rien enregistrer
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowAllNotes();
    }

    private void SaveButton_Click(object sender, RoutedEventArgs e)
    {
        // 1. Récupérer le texte saisi
        _note.Text = NoteText.Text;

        // 2. Première sauvegarde : choisir un nom de fichier unique
        if (_note.Filename == null)
        {
            _note.Filename = "note-" + DateTime.Now.ToString("yyyyMMdd-HHmmss-fff") + ".txt";
        }

        // 3. Écrire le fichier sur le disque
        Directory.CreateDirectory(MainWindow.NotesFolder);
        string path = Path.Combine(MainWindow.NotesFolder, _note.Filename);
        File.WriteAllText(path, _note.Text);
        _note.Date = File.GetLastWriteTime(path);

        // 4. Prévenir l'utilisateur et revenir à la liste
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowMessage("Note enregistrée");
        mainWindow.ShowAllNotes();
    }

    private async void DeleteButton_Click(object sender, RoutedEventArgs e)
    {
        // Une note jamais enregistrée n'a pas de fichier : rien à supprimer
        if (_note.Filename == null)
        {
            return;
        }
        string filename = _note.Filename;

        // 1. Demander confirmation et attendre la réponse de l'utilisateur
        ConfirmDialog dialog = new ConfirmDialog("Supprimer cette note ?");
        object? answer = await DialogHost.Show(dialog, "RootDialog");
        bool confirmed = object.Equals(answer, true);
        if (!confirmed)
        {
            return;
        }

        // 2. Supprimer le fichier
        string path = Path.Combine(MainWindow.NotesFolder, filename);
        if (File.Exists(path))
        {
            File.Delete(path);
        }

        // 3. Prévenir l'utilisateur et revenir à la liste
        MainWindow mainWindow = (MainWindow)Window.GetWindow(this);
        mainWindow.ShowMessage("Note supprimée");
        mainWindow.ShowAllNotes();
    }

    // Affiche la date en haut de l'écran, et n'active Supprimer que pour une note déjà enregistrée
    private void UpdateDisplay()
    {
        if (_note.Filename == null)
        {
            DateText.Text = "Nouvelle note";
            DeleteButton.IsEnabled = false;
        }
        else
        {
            DateText.Text = "Enregistrée le " + _note.Date.ToString("dd/MM/yyyy HH:mm");
            DeleteButton.IsEnabled = true;
        }
    }
}
Notion — async et await : attendre sans bloquer
Ouvrir la boîte de dialogue est immédiat, mais la réponse n'arrive que quand l'utilisateur clique, peut-être dix secondes plus tard. DialogHost.Show(…) renvoie donc une tâche (Task) qui se terminera à ce moment-là. await signifie « attends la fin de cette tâche, puis continue ici ». Pendant l'attente, la fenêtre reste vivante : elle se redessine, et les clics sont traités. Une méthode qui contient await doit être marquée async.
Depuis PHP — pourquoi ne pas simplement attendre ?
En PHP, une instruction qui attend (une requête SQL, un appel HTTP) bloque le script, et ce n'est pas grave : personne ne regarde la page pendant qu'elle se construit. Dans une application de bureau, bloquer revient à geler la fenêtre : plus de dessin, plus de clic… y compris sur le bouton de la boîte de dialogue qu'on attend. await évite ce piège. Si tu as écrit du JavaScript, c'est le même async / await.
Ce que fait ce code — DeleteButton_Click
  • using MaterialDesignThemes.Wpf; — pour pouvoir utiliser la classe DialogHost.
  • if (_note.Filename == null) { return; } — une sortie anticipée : sans fichier, rien à supprimer, on quitte la méthode tout de suite. return; fonctionne comme en PHP.
  • string filename = _note.Filename; — après ce test, le compilateur sait que le nom n'est pas nul : on le range dans une variable de type string, qu'on utilise plus bas.
  • object? answer = await DialogHost.Show(dialog, "RootDialog"); — ouvre la boîte de dialogue dans le DialogHost nommé RootDialog, attend la réponse, et la range dans answer. Son type est object? : n'importe quel objet, ou null si la boîte se ferme sans réponse.
  • object.Equals(answer, true) — vrai seulement si la réponse est le booléen true, l'équivalent de $answer === true en PHP. Cette méthode accepte une réponse nulle sans erreur.
  • if (!confirmed) { return; } — ! signifie « non » : si l'utilisateur n'a pas confirmé, on s'arrête là.
  • Ensuite seulement, le fichier est supprimé (File.Delete, l'équivalent de unlink()), un message est affiché et on revient à la liste, qui ne contient plus la note.
Ce que fait ce code — UpdateDisplay
La méthode règle maintenant aussi le bouton Supprimer, à l'ouverture de l'écran : grisé pour une note neuve, qui n'a pas encore de fichier, actif pour une note déjà enregistrée. IsEnabled est la propriété qui active ou désactive un contrôle. Pas besoin de la mettre à jour après un enregistrement : on revient aussitôt à la liste.
Point de vigilance — async void, seulement pour les événements
Une méthode async renvoie normalement une Task, que l'appelant peut attendre. async void est réservé aux gestionnaires d'événements comme DeleteButton_Click, parce que WPF impose leur signature : ils doivent renvoyer void. Ailleurs, écris async Task.
À tester (F5)
  1. Clique sur « + » : le bouton Supprimer est grisé. Clique sur Annuler.
  2. Ouvre une note existante : Supprimer est actif. Clique dessus : la fenêtre s'assombrit et la boîte de confirmation apparaît.
  3. Dans la boîte de dialogue, clique sur Annuler (ou appuie sur Échap) : rien n'est supprimé, la note reste affichée.
  4. Clique à nouveau sur Supprimer, puis confirme : « Note supprimée » s'affiche, tu reviens à la liste, et la carte a disparu. Le fichier n'est plus dans le dossier des notes.

Étape 3 — Et si on voulait tester ce code ?

Test unitaire, et ce qui l'empêche ici.

L'application fonctionne. Mais à chaque modification, il faut tout revérifier à la main : créer une note, l'enregistrer, la rouvrir, la supprimer… Un test unitaire ferait ces vérifications automatiquement, en quelques millisecondes.

Depuis PHP — comme un test PHPUnit

Dans un projet Laravel, tu écrirais par exemple :

Exemple en PHP (Laravel)
public function test_annuler_ne_supprime_pas_la_note(): void
{
    Storage::fake('notes');                  // un faux disque, en mémoire
    Storage::disk('notes')->put('note-1.txt', 'À garder');

    // ... appeler le code qui supprime, en simulant la réponse « Annuler »

    Storage::disk('notes')->assertExists('note-1.txt');
}

Le test ne touche ni au vrai disque, ni à une vraie personne qui clique : Laravel permet de remplacer le disque par un faux, et le test vérifie le résultat avec assertExists.

3.1 — À toi : le test impossible

On voudrait le même test pour NoteApp : « quand l'utilisateur répond Annuler, aucun fichier n'est supprimé ». Relis DeleteButton_Click et dresse la liste de tout ce qu'il faudrait mettre en place pour l'exécuter dans un test, sans fenêtre et sans personne devant l'écran.

À faire avant de lire la suite
Note chaque obstacle que tu trouves, et pour chacun, la ligne de code qui le provoque. Il y en a au moins cinq.

3.2 — Les obstacles

Ligne en causeCe qui empêche le test
InitializeComponent()Créer un NoteView construit de vrais objets WPF : il faut l'environnement graphique de Windows, même pour un test.
private … DeleteButton_ClickLa logique est dans un gestionnaire de clic privé : pour l'exécuter, il faudrait simuler un clic sur le bouton.
DialogHost.Show(…)La boîte de dialogue attend un vrai clic. Impossible de lui faire répondre « Annuler » automatiquement.
File.Delete(path)Le code écrit dans le vrai dossier des notes : un test risquerait d'effacer tes vraies notes.
Window.GetWindow(this)L'écran doit se trouver dans une vraie MainWindow, sinon la conversion échoue.
new ConfirmDialog(…)L'écran crée lui-même ce dont il a besoin : on ne peut pas lui fournir une version de test.

Tous ces obstacles ont la même cause : la logique (décider de supprimer, choisir le fichier) est mélangée avec l'interface (le clic, la boîte de dialogue, la fenêtre) et avec le disque.

Depuis PHP — la solution, tu la connais déjà
Dans Laravel, on évite de tout écrire dans le contrôleur : on range la logique dans des classes de service, qu'on reçoit dans le constructeur, et qu'un test peut remplacer par des faux. C'est exactement ce que fait le patron MVVM : la logique part dans des ViewModels sans aucun lien avec WPF, le disque et la boîte de dialogue se cachent derrière des interfaces, et l'injection de dépendances assemble le tout. C'est l'objet de la version suivante de NoteApp.
