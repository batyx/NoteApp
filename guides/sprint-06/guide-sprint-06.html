Supprimer et prévenir la liste

Au sprint 5, une note neuve n'apparaissait pas dans la liste. Dans ce sprint, tu fais communiquer les ViewModels par des messages, sans qu'ils se connaissent. Puis tu ajoutes la suppression, avec sa boîte de dialogue de confirmation, cachée derrière une interface comme le reste.

Où en est-on ? Que va-t-on faire ?

À la fin du sprint 5, on crée, ouvre, modifie et enregistre des notes, et MainViewModel change d'écran. Mais AllNotesViewModel n'est chargé qu'au démarrage, et NoteViewModel ne le connaît pas : une note neuve n'apparaît dans la liste qu'au lancement suivant. Et il manque toujours la suppression.

Pour ce sprint : deux étapes.

  • Étape 1 — prévenir la liste par un message après chaque enregistrement.
  • Étape 2 — supprimer une note, après une confirmation, avec un bouton grisé pour une note neuve.
1

Étape 1 — Prévenir la liste par un message

Messenger, classe de message, ObservableRecipient, IRecipient.

1.1 — Le principe

Notion — le Messenger, une boîte aux lettres
Le Messenger du Toolkit est une boîte aux lettres partagée. Un objet y envoie un message (Send) ; tous les objets abonnés à ce type de message le reçoivent (Receive). L'émetteur ne sait pas qui reçoit, ni même si quelqu'un reçoit : NoteViewModel annonce « cette note vient d'être enregistrée » sans connaître la liste.
Depuis PHP — comme les événements Laravel
C'est le principe des événements de Laravel : le code qui enregistre une note écrit event(new NoteSaved($note));, et un ou plusieurs listeners réagissent, sans que le code émetteur les connaisse. Ici, le message est l'événement, et le ViewModel qui le reçoit est le listener.

1.2 — Les deux messages

Un message est une simple classe qui transporte des données. Dans WpfNotes.Core, crée un dossier Messages et deux classes :

WpfNotes.Core/Messages/NoteSavedMessage.cs — nouveau fichier
using WpfNotes.Core.Models;

namespace WpfNotes.Core.Messages;

// Message envoyé par NoteViewModel après un enregistrement
public class NoteSavedMessage
{
    public NoteSavedMessage(Note note)
    {
        Note = note;
    }

    // La note enregistrée
    public Note Note { get; }
}
WpfNotes.Core/Messages/NoteDeletedMessage.cs — nouveau fichier
using WpfNotes.Core.Models;

namespace WpfNotes.Core.Messages;

// Message envoyé par NoteViewModel après une suppression
public class NoteDeletedMessage
{
    public NoteDeletedMessage(Note note)
    {
        Note = note;
    }

    // La note supprimée
    public Note Note { get; }
}
Ce que fait ce code
public Note Note { get; } — une propriété en lecture seule, affectée une fois pour toutes dans le constructeur. Un message ne change pas après son envoi. Le message de suppression ne sert qu'à l'étape 2, mais on l'écrit maintenant, avec son jumeau.

1.3 — La liste reçoit les messages

Remplace le contenu de AllNotesViewModel.cs :

WpfNotes.Core/ViewModels/AllNotesViewModel.cs
using System.Collections.ObjectModel;
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;
using CommunityToolkit.Mvvm.Messaging;
using WpfNotes.Core.Messages;
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;

namespace WpfNotes.Core.ViewModels;

// La logique de l'écran « liste des notes », sans aucun lien avec WPF.
// Elle reçoit les messages envoyés après un enregistrement ou une suppression.
public partial class AllNotesViewModel : ObservableRecipient,
    IRecipient<NoteSavedMessage>,
    IRecipient<NoteDeletedMessage>
{
    private readonly IFileService _fileService;
    private readonly INavigationService _navigationService;

    public AllNotesViewModel(IFileService fileService, INavigationService navigationService, IMessenger messenger)
        : base(messenger)
    {
        _fileService = fileService;
        _navigationService = navigationService;

        // Commencer à recevoir les messages
        IsActive = true;
    }

    // Les notes affichées par la vue, la plus récente en premier
    public ObservableCollection<Note> Notes { get; } = new ObservableCollection<Note>();

    // Lit les notes et remplit la collection
    public void LoadNotes()
    {
        List<Note> notes = _fileService.GetNotes();
        List<Note> sortedNotes = notes.OrderByDescending(note => note.Date).ToList();

        Notes.Clear();
        foreach (Note note in sortedNotes)
        {
            Notes.Add(note);
        }
    }

    // Bouton « + » : ouvrir une note neuve
    [RelayCommand]
    private void NewNote()
    {
        Note newNote = new Note();
        _navigationService.NavigateToNote(newNote);
    }

    // Clic sur une carte : ouvrir la note qu'elle affiche
    [RelayCommand]
    private void OpenNote(Note note)
    {
        _navigationService.NavigateToNote(note);
    }

    // Une note vient d'être enregistrée : elle passe en tête de la liste
    public void Receive(NoteSavedMessage message)
    {
        Notes.Remove(message.Note);
        Notes.Insert(0, message.Note);
    }

    // Une note vient d'être supprimée : elle quitte la liste
    public void Receive(NoteDeletedMessage message)
    {
        Notes.Remove(message.Note);
    }
}
Ce que fait ce code
  • ObservableRecipient — une autre classe de base du Toolkit : un ObservableObject qui sait en plus recevoir des messages. Elle reçoit le Messenger dans son constructeur.
  • : base(messenger) — transmet le Messenger au constructeur de la classe parente, comme parent::__construct($messenger) en PHP.
  • IRecipient<NoteSavedMessage> et IRecipient<NoteDeletedMessage> — la même interface générique, réalisée deux fois, pour deux types de messages. Chacune impose une méthode Receive, avec le bon type de paramètre.
  • IsActive = true; — abonne le ViewModel à tous les messages qu'il sait recevoir.
  • Receive(NoteSavedMessage message) — retire la note de la liste (si elle y était), puis l'insère en tête. Une note neuve apparaît, une note modifiée remonte.
  • Receive(NoteDeletedMessage message) — retire la note. Remove compare les références : c'est le même objet Note que celui de la carte.

1.4 — L'écran d'une note envoie le message

Remplace le contenu de NoteViewModel.cs par cette version : le Messenger arrive dans le constructeur, et Save envoie le message.

WpfNotes.Core/ViewModels/NoteViewModel.cs — version de l'étape 1
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;
using CommunityToolkit.Mvvm.Messaging;
using WpfNotes.Core.Messages;
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;

namespace WpfNotes.Core.ViewModels;

// La logique de l'écran « une note »
public partial class NoteViewModel : ObservableObject
{
    private readonly Note _note;
    private readonly IFileService _fileService;
    private readonly INotificationService _notificationService;
    private readonly INavigationService _navigationService;
    private readonly IMessenger _messenger;

    public NoteViewModel(
        Note note,
        IFileService fileService,
        INotificationService notificationService,
        INavigationService navigationService,
        IMessenger messenger)
    {
        _note = note;
        _fileService = fileService;
        _notificationService = notificationService;
        _navigationService = navigationService;
        _messenger = messenger;

        Text = note.Text;
    }

    // Le texte en cours d'édition, lié au champ de saisie de la vue
    [ObservableProperty]
    private string _text = "";

    // La ligne affichée en haut de l'écran
    public string DateText
    {
        get
        {
            if (_note.Filename == null)
            {
                return "Nouvelle note";
            }
            return "Enregistrée le " + _note.Date.ToString("dd/MM/yyyy HH:mm");
        }
    }

    // Bouton Annuler : revenir à la liste sans rien enregistrer
    [RelayCommand]
    private void Cancel()
    {
        _navigationService.NavigateToAllNotes();
    }

    // Bouton Enregistrer : écrire la note, prévenir la liste et l'utilisateur, revenir à la liste
    [RelayCommand]
    private void Save()
    {
        _note.Text = Text;
        _fileService.SaveNote(_note);

        _messenger.Send(new NoteSavedMessage(_note));
        _notificationService.Show("Note enregistrée");
        _navigationService.NavigateToAllNotes();
    }
}
Ce que fait ce code
_messenger.Send(new NoteSavedMessage(_note)); — crée le message et le dépose dans la boîte aux lettres. AllNotesViewModel le reçoit aussitôt, avant même la ligne suivante. L'ordre compte : le message part avant le retour à la liste, qui s'affiche donc déjà à jour.

1.5 — Faire circuler le Messenger

Les deux ViewModels doivent utiliser le même Messenger, sinon les messages n'arriveraient pas. MainViewModel le reçoit et le transmet. Remplace le contenu de MainViewModel.cs :

WpfNotes.Core/ViewModels/MainViewModel.cs — version de l'étape 1
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Messaging;
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;

namespace WpfNotes.Core.ViewModels;

// Le ViewModel de la fenêtre. Il expose l'écran courant, et c'est lui qui change d'écran :
// il joue donc aussi le rôle du service de navigation.
public partial class MainViewModel : ObservableObject, INavigationService
{
    private readonly IFileService _fileService;
    private readonly INotificationService _notificationService;
    private readonly IMessenger _messenger;
    private readonly AllNotesViewModel _allNotesViewModel;

    public MainViewModel(
        IFileService fileService,
        INotificationService notificationService,
        IMessenger messenger)
    {
        _fileService = fileService;
        _notificationService = notificationService;
        _messenger = messenger;

        // La liste existe pendant toute la vie de l'application ; « this » est son service de navigation
        _allNotesViewModel = new AllNotesViewModel(fileService, this, messenger);
        _allNotesViewModel.LoadNotes();

        // Au démarrage, on affiche la liste
        NavigateToAllNotes();
    }

    // Le ViewModel de l'écran affiché ; la fenêtre choisit la vue qui lui correspond
    [ObservableProperty]
    private object? _currentViewModel;

    public void NavigateToAllNotes()
    {
        CurrentViewModel = _allNotesViewModel;
    }

    public void NavigateToNote(Note note)
    {
        NoteViewModel noteViewModel = new NoteViewModel(
            note, _fileService, _notificationService, this, _messenger);
        CurrentViewModel = noteViewModel;
    }
}

Dans App.xaml.cs, crée le Messenger et donne-le à MainViewModel :

WpfNotes/App.xaml.cs — version de l'étape 1
using System.Windows;
using CommunityToolkit.Mvvm.Messaging;
using MaterialDesignThemes.Wpf;
using WpfNotes.Core.Services;
using WpfNotes.Core.ViewModels;
using WpfNotes.Services;

namespace WpfNotes;

public partial class App : Application
{
    protected override void OnStartup(StartupEventArgs e)
    {
        base.OnStartup(e);

        // On assemble l'application à la main : chaque objet reçoit ce dont il a besoin
        IFileService fileService = new FileService();
        SnackbarMessageQueue messageQueue = new SnackbarMessageQueue(TimeSpan.FromSeconds(2));
        INotificationService notificationService = new NotificationService(messageQueue);
        IMessenger messenger = WeakReferenceMessenger.Default;
        MainViewModel mainViewModel = new MainViewModel(fileService, notificationService, messenger);

        MainWindow mainWindow = new MainWindow(mainViewModel, messageQueue);
        mainWindow.Show();
    }
}
Ce que fait ce code
  • IMessenger — le contrat d'un Messenger, fourni par le Toolkit. Les ViewModels ne connaissent que lui.
  • WeakReferenceMessenger.Default — la réalisation fournie par le Toolkit, dans une instance unique partagée par toute l'application. Weak reference (référence faible) : le Messenger ne garde pas en vie un destinataire que plus personne n'utilise.

Étape 2 — Supprimer après confirmation

IDialogService, commande asynchrone, CanExecute, bouton grisé automatiquement.

2.1 — Le contrat de la boîte de dialogue

Notion — à quoi sert IDialogService ?
Dans la version code-behind, l'écran appelait directement DialogHost.Show(…) : impossible de tester sans un vrai clic. IDialogService sera utilisé par NoteViewModel, et aura deux réalisations : DialogService, dans le projet WPF, qui ouvre le vrai DialogHost, et FakeDialogService, au sprint 8, qui répond « oui » ou « non » selon ce que le test a décidé. Le ViewModel pose sa question de la même façon aux deux.
WpfNotes.Core/Services/IDialogService.cs — nouveau fichier
namespace WpfNotes.Core.Services;

// Poser une question à l'utilisateur.
// L'implémentation réelle utilise le DialogHost de MaterialDesign, dans le projet WPF.
public interface IDialogService
{
    // Demande une confirmation ; renvoie true si l'utilisateur accepte
    Task<bool> ConfirmAsync(string message);
}
Ce que fait ce code
Task<bool> ConfirmAsync(string message); — la réponse n'arrive que quand l'utilisateur clique : la méthode renvoie une tâche qui donnera un bool à ce moment-là. Par convention, le nom d'une méthode asynchrone se termine par Async.

WpfNotes/Services/DialogService.cs — nouveau fichier
using MaterialDesignThemes.Wpf;
using WpfNotes.Core.Services;
using WpfNotes.Views;

namespace WpfNotes.Services;

// L'implémentation réelle de IDialogService : le DialogHost de MaterialDesign
public class DialogService : IDialogService
{
    public async Task<bool> ConfirmAsync(string message)
    {
        // "RootDialog" est l'Identifier du DialogHost déclaré dans MainWindow.xaml
        ConfirmDialog dialog = new ConfirmDialog(message);
        object? answer = await DialogHost.Show(dialog, "RootDialog");
        bool confirmed = object.Equals(answer, true);
        return confirmed;
    }
}
Ce que fait ce code
C'est le code du DeleteButton_Click du sprint 3, déplacé ici : ouvrir la boîte, attendre la réponse avec await, la comparer à true. return confirmed; renvoie la réponse ; comme la méthode est async, l'appelant reçoit une Task<bool>.

2.3 — La commande Supprimer

Remplace le contenu de NoteViewModel.cs par sa version finale :

WpfNotes.Core/ViewModels/NoteViewModel.cs
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;
using CommunityToolkit.Mvvm.Messaging;
using WpfNotes.Core.Messages;
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;

namespace WpfNotes.Core.ViewModels;

// La logique de l'écran « une note »
public partial class NoteViewModel : ObservableObject
{
    private readonly Note _note;
    private readonly IFileService _fileService;
    private readonly IDialogService _dialogService;
    private readonly INotificationService _notificationService;
    private readonly INavigationService _navigationService;
    private readonly IMessenger _messenger;

    public NoteViewModel(
        Note note,
        IFileService fileService,
        IDialogService dialogService,
        INotificationService notificationService,
        INavigationService navigationService,
        IMessenger messenger)
    {
        _note = note;
        _fileService = fileService;
        _dialogService = dialogService;
        _notificationService = notificationService;
        _navigationService = navigationService;
        _messenger = messenger;

        Text = note.Text;
    }

    // Le texte en cours d'édition, lié au champ de saisie de la vue
    [ObservableProperty]
    private string _text = "";

    // La ligne affichée en haut de l'écran
    public string DateText
    {
        get
        {
            if (_note.Filename == null)
            {
                return "Nouvelle note";
            }
            return "Enregistrée le " + _note.Date.ToString("dd/MM/yyyy HH:mm");
        }
    }

    // Bouton Annuler : revenir à la liste sans rien enregistrer
    [RelayCommand]
    private void Cancel()
    {
        _navigationService.NavigateToAllNotes();
    }

    // Bouton Enregistrer : écrire la note, prévenir la liste et l'utilisateur, revenir à la liste
    [RelayCommand]
    private void Save()
    {
        _note.Text = Text;
        _fileService.SaveNote(_note);

        _messenger.Send(new NoteSavedMessage(_note));
        _notificationService.Show("Note enregistrée");
        _navigationService.NavigateToAllNotes();
    }

    // Bouton Supprimer : seulement pour une note déjà enregistrée (voir CanDelete)
    [RelayCommand(CanExecute = nameof(CanDelete))]
    private async Task DeleteAsync()
    {
        if (_note.Filename == null)
        {
            return;
        }
        string filename = _note.Filename;

        // 1. Demander confirmation et attendre la réponse
        bool confirmed = await _dialogService.ConfirmAsync("Supprimer cette note ?");
        if (!confirmed)
        {
            return;
        }

        // 2. Supprimer le fichier
        _fileService.DeleteNote(filename);

        // 3. Prévenir la liste et l'utilisateur, revenir à la liste
        _messenger.Send(new NoteDeletedMessage(_note));
        _notificationService.Show("Note supprimée");
        _navigationService.NavigateToAllNotes();
    }

    // Une note neuve n'a pas encore de fichier : rien à supprimer, le bouton est grisé
    private bool CanDelete()
    {
        return _note.Filename != null;
    }
}
Code généré par le Toolkit — une commande asynchrone, avec condition

Devant DeleteAsync(), qui renvoie une Task, [RelayCommand] génère une commande asynchrone, nommée sans le suffixe Async : DeleteCommand. CanExecute = nameof(CanDelete) lui associe la méthode qui dit si elle peut s'exécuter. En simplifiant :

Code généré (simplifié) — la commande DeleteCommand
private AsyncRelayCommand? _deleteCommand;

public IAsyncRelayCommand DeleteCommand
{
    get
    {
        if (_deleteCommand == null)
        {
            // la commande appellera DeleteAsync(), seulement si CanDelete() renvoie true
            _deleteCommand = new AsyncRelayCommand(DeleteAsync, CanDelete);
        }
        return _deleteCommand;
    }
}

nameof(CanDelete) donne le texte "CanDelete", vérifié par le compilateur : une faute de frappe dans le nom serait signalée.

Notion — CanExecute, un bouton grisé sans une ligne de code dans la vue
Un bouton relié à une commande demande à cette commande si elle peut s'exécuter. Si CanDelete() renvoie false, le bouton Supprimer est grisé automatiquement. Au sprint 3, il fallait écrire DeleteButton.IsEnabled = false; dans le code-behind. Ici, la règle « une note neuve ne se supprime pas » vit dans le ViewModel, où un test pourra la vérifier.
Ce que fait ce code
  • Le constructeur reçoit en plus IDialogService.
  • private async Task DeleteAsync() — une méthode asynchrone qui renvoie une Task, et non void : ce n'est plus un gestionnaire d'événement, et la commande (comme un test) peut attendre sa fin.
  • await _dialogService.ConfirmAsync(…) — pose la question par le contrat. Le ViewModel ne sait pas si c'est une vraie boîte de dialogue ou un faux.
  • Après la suppression : le message NoteDeletedMessage pour la liste, la notification, et le retour à la liste.

À tester (F5)
  1. Clique sur « + » : Supprimer est grisé. Clique sur Annuler.
  2. Ouvre une note existante : Supprimer est actif. Clique dessus : la boîte de confirmation apparaît.
  3. Dans la boîte, clique sur Annuler : rien n'est supprimé, la note reste affichée.
  4. Clique à nouveau sur Supprimer, puis confirme : « Note supprimée » s'affiche, tu reviens à la liste, et la carte a disparu.
