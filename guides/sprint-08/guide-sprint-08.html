Étape 1 — Le projet de tests

xUnit, référence vers la seule bibliothèque, anatomie d'un test.

Étapes dans Visual Studio
  1. Clic droit sur la solution → Ajouter → Nouveau projet… → Projet de test xUnit (C#).
  2. Nom : WpfNotes.Tests. Framework : .NET 10.0.
  3. Supprime le fichier UnitTest1.cs généré.
  4. Clic droit sur WpfNotes.Tests → Ajouter → Référence de projet… → coche seulement WpfNotes.Core.

Ce que fait ce code
  • xunit — le framework de test : les attributs [Fact], [Theory] et la classe Assert.
  • Microsoft.NET.Test.Sdk et xunit.runner.visualstudio — ce qui permet à Visual Studio (et à dotnet test) de trouver et lancer les tests.
  • <Using Include="Xunit" /> — ajoute using Xunit; dans tous les fichiers du projet.
  • IsPackable = false — ce projet ne sera jamais distribué.
Notion — les tests ne référencent que la bibliothèque
Le projet de tests cible net10.0 et ne connaît que WpfNotes.Core : aucune fenêtre, aucun contrôle, aucun MaterialDesign. C'est la règle d'or du sprint 4 qui paie : tout ce qui mérite d'être testé est dans la bibliothèque. Ces tests peuvent même tourner sur un serveur Linux, sans écran.
Depuis PHP — un test xUnit et un test PHPUnit
PHPUnit
class NoteTest extends TestCase
{
    public function test_texte_par_defaut(): void
    {
        // Arrange
        $note = new Note();

        // Act
        $text = $note->text;

        // Assert
        $this->assertEquals('', $text);
    }
}
xUnit
public class NoteTests
{
    [Fact]
    public void Text_ByDefault_IsEmpty()
    {
        // Arrange
        Note note = new Note();

        // Act
        string text = note.Text;

        // Assert
        Assert.Equal("", text);
    }
}
  • Pas de classe parente : c'est l'attribut [Fact] qui désigne une méthode de test.
  • $this->assertEquals devient Assert.Equal, avec le même ordre : la valeur attendue d'abord, la valeur obtenue ensuite.
  • Les trois temps Arrange (préparer), Act (agir), Assert (vérifier) sont les mêmes.
  • Convention de nommage des tests de ce guide : Méthode_Situation_RésultatAttendu.

Étape 2 — Les services factices

Fake, la seconde réalisation de chaque interface.

Notion — le fake, une doublure de test
Pour tester NoteViewModel, il faut lui fournir ses services. Les vrais touchent au disque ou affichent des fenêtres. On écrit donc des fakes : d'autres réalisations des mêmes interfaces, qui font semblant et retiennent ce qu'on leur a demandé. C'est la promesse faite à chaque nouvelle interface depuis le sprint 4 : le ViewModel respecte le contrat, et accepte donc n'importe quelle réalisation.
Depuis PHP — les fakes de Laravel
Laravel en fournit tout prêts : Storage::fake() remplace le disque par un disque en mémoire, Mail::fake() retient les mails au lieu de les envoyer, Event::fake() retient les événements. Ici, on les écrit soi-même, ce qui montre qu'il n'y a là rien de magique.

Dans WpfNotes.Tests, crée un dossier Fakes et quatre classes :

WpfNotes.Tests/Fakes/FakeFileService.cs — nouveau fichier
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;

namespace WpfNotes.Tests.Fakes;

// Un faux service de fichiers : les notes restent en mémoire, aucun fichier n'est touché
public class FakeFileService : IFileService
{
    private int _counter = 0;

    // Les notes « enregistrées ». Un test peut en ajouter avant d'agir.
    public List<Note> Notes { get; } = new List<Note>();

    // Les noms de fichiers supprimés, dans l'ordre
    public List<string> DeletedFilenames { get; } = new List<string>();

    public List<Note> GetNotes()
    {
        List<Note> copy = new List<Note>(Notes);
        return copy;
    }

    public void SaveNote(Note note)
    {
        if (note.Filename == null)
        {
            _counter = _counter + 1;
            note.Filename = "note-" + _counter + ".txt";
        }

        // Une date fixe : un test ne doit pas dépendre de l'heure à laquelle il s'exécute
        note.Date = new DateTime(2026, 1, 1, 12, 0, 0);

        if (!Notes.Contains(note))
        {
            Notes.Add(note);
        }
    }

    public void DeleteNote(string filename)
    {
        DeletedFilenames.Add(filename);
    }
}
WpfNotes.Tests/Fakes/FakeDialogService.cs — nouveau fichier
using WpfNotes.Core.Services;

namespace WpfNotes.Tests.Fakes;

// Une fausse boîte de dialogue : elle répond ce que le test a décidé, sans rien afficher
public class FakeDialogService : IDialogService
{
    // La réponse que donnera « l'utilisateur »
    public bool Answer { get; set; }

    // Le nombre de fois où une confirmation a été demandée
    public int CallCount { get; private set; }

    public Task<bool> ConfirmAsync(string message)
    {
        CallCount = CallCount + 1;
        return Task.FromResult(Answer);
    }
}

WpfNotes.Tests/Fakes/FakeNavigationService.cs — nouveau fichier
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;

namespace WpfNotes.Tests.Fakes;

// Un faux service de navigation : il retient les écrans demandés au lieu de les afficher
public class FakeNavigationService : INavigationService
{
    // Le nombre de retours à la liste demandés
    public int NavigatedToAllNotesCount { get; private set; }

    // La dernière note qu'on a demandé d'ouvrir, ou null si aucune
    public Note? LastOpenedNote { get; private set; }

    public void NavigateToAllNotes()
    {
        NavigatedToAllNotesCount = NavigatedToAllNotesCount + 1;
    }

    public void NavigateToNote(Note note)
    {
        LastOpenedNote = note;
    }
}
Ce que fait ce code
  • FakeFileService — garde les notes dans une liste, et retient les noms de fichiers supprimés. La date est toujours la même : un test doit donner le même résultat à chaque exécution. new List<Note>(Notes) renvoie une copie de la liste, comme le ferait le vrai service.
  • FakeDialogService — c'est le test qui choisit la réponse de « l'utilisateur » (Answer). Task.FromResult(Answer) crée une tâche déjà terminée, avec cette réponse : pas d'attente réelle.
  • FakeNotificationService et FakeNavigationService — ils retiennent les messages et les écrans demandés, pour que le test puisse les vérifier.
  • { get; private set; } — une propriété qu'on peut lire de partout, mais modifier seulement depuis sa propre classe : le test lit le compteur, il ne le trafique pas.

Étape 3 — Tester NoteViewModel

Fact, Assert, commandes, messages, test asynchrone.

Crée un dossier ViewModels dans WpfNotes.Tests, puis la classe de tests :

WpfNotes.Tests/ViewModels/NoteViewModelTests.cs — nouveau fichier
using CommunityToolkit.Mvvm.Messaging;
using WpfNotes.Core.Messages;
using WpfNotes.Core.Models;
using WpfNotes.Core.ViewModels;
using WpfNotes.Tests.Fakes;

namespace WpfNotes.Tests.ViewModels;

// Les tests de NoteViewModel, avec des fakes écrits à la main.
// xUnit crée un nouvel objet de cette classe pour CHAQUE test : les champs ci-dessous
// sont donc neufs à chaque fois, et les tests ne peuvent pas se gêner entre eux.
public class NoteViewModelTests
{
    private readonly FakeFileService _fileService = new FakeFileService();
    private readonly FakeDialogService _dialogService = new FakeDialogService();
    private readonly FakeNotificationService _notificationService = new FakeNotificationService();
    private readonly FakeNavigationService _navigationService = new FakeNavigationService();

    // Un Messenger neuf pour chaque test, au lieu de WeakReferenceMessenger.Default partagé
    private readonly IMessenger _messenger = new WeakReferenceMessenger();

    // Crée le ViewModel à tester, avec tous les fakes
    private NoteViewModel CreateViewModel(Note note)
    {
        NoteViewModel viewModel = new NoteViewModel(
            note, _fileService, _dialogService, _notificationService, _navigationService, _messenger);
        return viewModel;
    }

    // Test 1 — Modifier le texte prévient la vue
    [Fact]
    public void Text_WhenChanged_RaisesPropertyChanged()
    {
        // Arrange
        NoteViewModel viewModel = CreateViewModel(new Note());

        // Act et Assert : l'action doit déclencher PropertyChanged pour la propriété "Text"
        Assert.PropertyChanged(viewModel, "Text", () => viewModel.Text = "Bonjour");
    }

    // Test 2 — Supprimer est grisé pour une note neuve
    [Fact]
    public void DeleteCommand_ForNewNote_CannotExecute()
    {
        // Arrange
        NoteViewModel viewModel = CreateViewModel(new Note());

        // Act
        bool canExecute = viewModel.DeleteCommand.CanExecute(null);

        // Assert
        Assert.False(canExecute);
    }

    // Test 3 — Enregistrer écrit la note
    [Fact]
    public void SaveCommand_WritesNoteToFileService()
    {
        // Arrange
        NoteViewModel viewModel = CreateViewModel(new Note());
        viewModel.Text = "Bonjour";

        // Act
        viewModel.SaveCommand.Execute(null);

        // Assert
        Note savedNote = Assert.Single(_fileService.Notes);
        Assert.Equal("Bonjour", savedNote.Text);
    }

    // Test 4 — Enregistrer prévient la liste par un message
    [Fact]
    public void SaveCommand_SendsNoteSavedMessage()
    {
        // Arrange : le test s'abonne lui-même au message
        NoteSavedMessage? receivedMessage = null;
        _messenger.Register<NoteSavedMessage>(this, (recipient, message) => receivedMessage = message);
        NoteViewModel viewModel = CreateViewModel(new Note());
        viewModel.Text = "Bonjour";

        // Act
        viewModel.SaveCommand.Execute(null);

        // Assert
        Assert.NotNull(receivedMessage);
        Assert.Equal("Bonjour", receivedMessage.Note.Text);
    }

    // Test 5 — Enregistrer revient à la liste
    [Fact]
    public void SaveCommand_NavigatesBackToList()
    {
        // Arrange
        NoteViewModel viewModel = CreateViewModel(new Note());

        // Act
        viewModel.SaveCommand.Execute(null);

        // Assert
        Assert.Equal(1, _navigationService.NavigatedToAllNotesCount);
    }

    // Test 6 — Annuler revient à la liste sans rien enregistrer
    [Fact]
    public void CancelCommand_NavigatesBackWithoutSaving()
    {
        // Arrange
        NoteViewModel viewModel = CreateViewModel(new Note());
        viewModel.Text = "Brouillon";

        // Act
        viewModel.CancelCommand.Execute(null);

        // Assert
        Assert.Empty(_fileService.Notes);
        Assert.Equal(1, _navigationService.NavigatedToAllNotesCount);
    }

    // Test 7 — Supprimer, puis répondre « non » : rien n'est supprimé
    [Fact]
    public async Task DeleteCommand_WhenUserSaysNo_DeletesNothing()
    {
        // Arrange : le fake répondra « non »
        _dialogService.Answer = false;
        Note note = new Note();
        note.Filename = "note-1.txt";
        NoteViewModel viewModel = CreateViewModel(note);

        // Act : la commande est asynchrone, on attend qu'elle se termine
        await viewModel.DeleteCommand.ExecuteAsync(null);

        // Assert
        Assert.Equal(1, _dialogService.CallCount);
        Assert.Empty(_fileService.DeletedFilenames);
        Assert.Empty(_notificationService.Messages);
    }

    // Test 8 — Supprimer, puis répondre « oui » : la note est supprimée, et tout le monde est prévenu
    [Fact]
    public async Task DeleteCommand_WhenUserSaysYes_DeletesNotifiesAndNavigates()
    {
        // Arrange
        _dialogService.Answer = true;
        Note note = new Note();
        note.Filename = "note-1.txt";
        NoteViewModel viewModel = CreateViewModel(note);

        // Act
        await viewModel.DeleteCommand.ExecuteAsync(null);

        // Assert
        Assert.Contains("note-1.txt", _fileService.DeletedFilenames);
        Assert.Single(_notificationService.Messages);
        Assert.Equal(1, _navigationService.NavigatedToAllNotesCount);
    }
}
Notion — un objet neuf pour chaque test
xUnit crée un nouvel objet NoteViewModelTests avant chaque test. Les champs (les fakes, le Messenger) sont donc neufs à chaque fois : un test ne peut pas hériter de ce qu'un autre a laissé. C'est pour cela qu'on utilise un new WeakReferenceMessenger() par test, et non l'instance partagée WeakReferenceMessenger.Default de l'application.
Ce que fait ce code
  • CreateViewModel(Note note) — une méthode d'aide qui fournit au ViewModel tous les fakes. C'est le même assemblage qu'au sprint 5, avec d'autres réalisations.
  • Test 1 — Assert.PropertyChanged(objet, "Text", action) exécute l'action et vérifie qu'elle déclenche PropertyChanged pour Text. () => viewModel.Text = "Bonjour" est une fonction fléchée sans paramètre, comme fn() => … en PHP.
  • Test 2 — la règle « une note neuve ne se supprime pas » se teste directement, par CanExecute. Au sprint 3, elle était cachée dans le code-behind.
  • Tests 3, 5, 6 — SaveCommand.Execute(null) exécute la commande comme le ferait le bouton ; null parce qu'elle n'a pas de paramètre. Assert.Single vérifie qu'il y a exactement un élément, et le renvoie.
  • Test 4 — le test s'abonne lui-même au message avec _messenger.Register. La fonction fléchée (recipient, message) => receivedMessage = message reçoit deux paramètres et range le message dans une variable locale, que l'on vérifie ensuite.
  • Tests 7 et 8 — la commande Supprimer est asynchrone : le test est une méthode async Task, et attend la fin de la commande avec await DeleteCommand.ExecuteAsync(null). _dialogService.Answer joue le rôle de l'utilisateur.
Retour au sprint 3 — le test impossible
Le test 7, « Supprimer, puis répondre non : rien n'est supprimé », est exactement celui qu'on n'arrivait pas à écrire au sprint 3. Il tient maintenant en une quinzaine de lignes, s'exécute en quelques millisecondes, et ne touche ni au disque ni à l'écran.
À tester (Explorateur de tests)
  1. Dans l'Explorateur de tests, clique sur « Exécuter tous les tests » : les 8 tests passent au vert.
  2. Vérifie qu'un test sait échouer : dans NoteViewModel.Save(), mets en commentaire la ligne _navigationService.NavigateToAllNotes();, puis relance les tests. Le test 5 passe au rouge, et son message dit ce qui était attendu et ce qui a été obtenu. Remets la ligne.

Étape 4 — Tester AllNotesViewModel

Test paramétré, boucle for, simuler un message.

WpfNotes.Tests/ViewModels/AllNotesViewModelTests.cs — nouveau fichier
using CommunityToolkit.Mvvm.Messaging;
using WpfNotes.Core.Messages;
using WpfNotes.Core.Models;
using WpfNotes.Core.ViewModels;
using WpfNotes.Tests.Fakes;

namespace WpfNotes.Tests.ViewModels;

// Les tests de AllNotesViewModel, avec des fakes écrits à la main
public class AllNotesViewModelTests
{
    private readonly FakeFileService _fileService = new FakeFileService();
    private readonly FakeNavigationService _navigationService = new FakeNavigationService();
    private readonly IMessenger _messenger = new WeakReferenceMessenger();

    private AllNotesViewModel CreateViewModel()
    {
        AllNotesViewModel viewModel = new AllNotesViewModel(_fileService, _navigationService, _messenger);
        return viewModel;
    }

    // Test 9 — Charger remplit la liste, quel que soit le nombre de notes.
    // [Theory] : le même test est exécuté une fois par ligne [InlineData].
    [Theory]
    [InlineData(0)]
    [InlineData(1)]
    [InlineData(3)]
    public void LoadNotes_FillsNotesFromFileService(int noteCount)
    {
        // Arrange
        for (int i = 1; i <= noteCount; i++)
        {
            Note note = new Note();
            note.Filename = "note-" + i + ".txt";
            _fileService.Notes.Add(note);
        }
        AllNotesViewModel viewModel = CreateViewModel();

        // Act
        viewModel.LoadNotes();

        // Assert
        Assert.Equal(noteCount, viewModel.Notes.Count);
    }

    // Test 10 — Recevoir « note supprimée » retire la note de la liste
    [Fact]
    public void ReceiveNoteDeletedMessage_RemovesNoteFromList()
    {
        // Arrange : deux notes dans la liste
        Note firstNote = new Note();
        firstNote.Filename = "note-1.txt";
        Note secondNote = new Note();
        secondNote.Filename = "note-2.txt";
        _fileService.Notes.Add(firstNote);
        _fileService.Notes.Add(secondNote);
        AllNotesViewModel viewModel = CreateViewModel();
        viewModel.LoadNotes();

        // Act : on envoie le message, comme le ferait NoteViewModel
        _messenger.Send(new NoteDeletedMessage(firstNote));

        // Assert
        Note remainingNote = Assert.Single(viewModel.Notes);
        Assert.Equal("note-2.txt", remainingNote.Filename);
    }

    // Test 11 — Le bouton « + » ouvre une note neuve
    [Fact]
    public void NewNoteCommand_NavigatesToNewNote()
    {
        // Arrange
        AllNotesViewModel viewModel = CreateViewModel();

        // Act
        viewModel.NewNoteCommand.Execute(null);

        // Assert : une note a été ouverte, et elle n'a pas encore de fichier
        Assert.NotNull(_navigationService.LastOpenedNote);
        Assert.Null(_navigationService.LastOpenedNote.Filename);
    }
}
Depuis PHP — [Theory], c'est un data provider
Avec PHPUnit, un data provider (#[DataProvider('counts')]) exécute le même test avec plusieurs jeux de données. [Theory] fait la même chose, et chaque [InlineData(…)] fournit un jeu : le test 9 est exécuté trois fois, avec 0, 1 et 3 notes.
Ce que fait ce code
  • for (int i = 1; i <= noteCount; i++) — la même boucle for qu'en PHP, avec le type de la variable. "note-" + i + ".txt" assemble un texte et un nombre.
  • Test 10 — _messenger.Send(…) simule ce que ferait NoteViewModel : le test vérifie la réaction de la liste sans faire intervenir l'écran d'une note.
  • Test 11 — la commande du bouton « + » demande l'ouverture d'une note qui n'a pas encore de fichier.
À tester (Explorateur de tests)
13 tests passent : les 8 de l'étape 3, et les 3 de cette étape, dont le test 9 compté trois fois.

Crée un dossier WithMocks et la classe :

WpfNotes.Tests/WithMocks/NoteViewModelMockTests.cs — nouveau fichier
using CommunityToolkit.Mvvm.Messaging;
using NSubstitute;
using WpfNotes.Core.Models;
using WpfNotes.Core.Services;
using WpfNotes.Core.ViewModels;

namespace WpfNotes.Tests.WithMocks;

// Les tests 3, 7 et 8 réécrits avec NSubstitute, à comparer avec leur version à fakes
public class NoteViewModelMockTests
{
    // Substitute.For<T>() fabrique un objet qui respecte l'interface, sans écrire de classe
    private readonly IFileService _fileService = Substitute.For<IFileService>();
    private readonly IDialogService _dialogService = Substitute.For<IDialogService>();
    private readonly INotificationService _notificationService = Substitute.For<INotificationService>();
    private readonly INavigationService _navigationService = Substitute.For<INavigationService>();
    private readonly IMessenger _messenger = new WeakReferenceMessenger();

    private NoteViewModel CreateViewModel(Note note)
    {
        NoteViewModel viewModel = new NoteViewModel(
            note, _fileService, _dialogService, _notificationService, _navigationService, _messenger);
        return viewModel;
    }

    // Test 3 avec un mock — vérifier l'argument reçu
    [Fact]
    public void SaveCommand_WritesNoteWithItsText()
    {
        // Arrange
        NoteViewModel viewModel = CreateViewModel(new Note());
        viewModel.Text = "Bonjour";

        // Act
        viewModel.SaveCommand.Execute(null);

        // Assert : SaveNote a été appelée une fois, avec une note dont le texte est "Bonjour"
        _fileService.Received(1).SaveNote(Arg.Is<Note>(note => note.Text == "Bonjour"));
    }

    // Test 7 avec un mock — configurer une réponse
    [Fact]
    public async Task DeleteCommand_WhenUserSaysNo_DeletesNothing()
    {
        // Arrange : « quand on te demande une confirmation, quelle que soit la question, réponds non »
        _dialogService.ConfirmAsync(Arg.Any<string>()).Returns(false);
        Note note = new Note();
        note.Filename = "note-1.txt";
        NoteViewModel viewModel = CreateViewModel(note);

        // Act
        await viewModel.DeleteCommand.ExecuteAsync(null);

        // Assert : DeleteNote n'a jamais été appelée
        _fileService.DidNotReceive().DeleteNote(Arg.Any<string>());
    }

    // Test 8 avec un mock — vérifier qu'un appel a eu lieu une seule fois
    [Fact]
    public async Task DeleteCommand_WhenUserSaysYes_NotifiesOnce()
    {
        // Arrange
        _dialogService.ConfirmAsync(Arg.Any<string>()).Returns(true);
        Note note = new Note();
        note.Filename = "note-1.txt";
        NoteViewModel viewModel = CreateViewModel(note);

        // Act
        await viewModel.DeleteCommand.ExecuteAsync(null);

        // Assert
        _notificationService.Received(1).Show("Note supprimée");
    }
}
Depuis PHP — comme Mockery
Avec Mockery, tu écrirais $dialog->shouldReceive('confirm')->andReturn(false); puis $files->shouldNotReceive('deleteNote');. NSubstitute s'écrit presque pareil, en appelant directement la méthode : _dialogService.ConfirmAsync(…).Returns(false);.
Ce que fait ce code
  • Substitute.For<IFileService>() — fabrique un objet qui réalise l'interface, sans écrire de classe. Par défaut, ses méthodes ne font rien et renvoient une valeur vide.
  • .Returns(false) — programme une réponse : « quand on appelle ConfirmAsync, réponds false ». Arg.Any<string>() signifie « quel que soit le message ».
  • .Received(1).Show("Note supprimée") — vérifie après coup que la méthode a été appelée une fois, avec ce texte. .DidNotReceive() vérifie qu'elle ne l'a jamais été.
  • Arg.Is<Note>(note => note.Text == "Bonjour") — accepte n'importe quelle note dont le texte vaut "Bonjour" : la fonction fléchée renvoie true ou false.
